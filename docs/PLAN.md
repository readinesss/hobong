# 호봉 (hobong) — 프로젝트 브리프

이 문서는 `hobong` 저장소에서 진행할 프로젝트의 기획 브리프다.
먼저 이 내용을 `docs/PLAN.md`로 저장하고, 맨 아래 "첫 작업" 순서대로 끝까지 진행해줘.
"(가정)" 표시가 있는 항목은 확정이 아니니, 더 나은 대안이 있으면 근거를 남기고 적용해줘.

## 한 줄 소개
공무원이 자기 호봉·월급·승급·연가·정년 등을 재미있게 확인하고 관리하는 픽셀아트 웹사이트.
호봉이 오를 때마다 진화하는 캐릭터 "호봉이"가 핵심 재미 요소.

## 목표
- 공무원 사이에서 바이럴될 것: 공유하고 싶고, 자꾸 들어와 확인하고 싶을 것
- 업무망(내부망, 인터넷 차단)에서도 그대로 동작할 것
- 법령·규정이 바뀌어도 데이터 파일만 고치면 될 것
- 데스크톱과 모바일 웹 모두에서 자연스럽게 쓸 수 있을 것

## 핵심 설계 원칙
1. 서버 없는 정적 사이트. 모든 계산은 브라우저에서 수행
2. 외부 요청 0건 (CDN, 웹폰트, 분석 도구, 외부 API 금지)
   → 단일 HTML로 빌드해 내부망 반입 가능
3. 입력값은 localStorage에만 저장. 데이터 파일 내려받기·불러오기로 세션 간 연속성 보장
4. 규정 값은 코드와 분리: `data/<연도>.json`에 봉급표·연가일수·승진 요건·공휴일을 두고,
   항목마다 근거 법령·조항·시행일을 함께 기록. 화면에 "OOOO년 기준" 표시
5. 계산 로직은 UI와 분리된 순수 함수 + 단위 테스트 (날짜 계산 오류가 가장 큰 위험)

## 적용 대상 (가정)
- 1차: 국가직 일반직 공무원 (9~6급 중심)
- 이후: 지방직, 다른 직종·직급 (근거 규정이 달라 데이터 파일을 분리)

## 기능

### MVP
입력: 임용일, 생년월일, 현재 직급·호봉, 다음 승급일, 닉네임
- 정년까지 남은 일수 / 근무일수
- 다음 정기승급일 D-day
- 근속승진 예정일, 대우공무원까지 남은 일수
- 월 봉급(봉급표 기준), 지금까지 번 돈(추정), 다음 인상 시점
- 연가 장부
- 데이터 내려받기·불러오기
- 호봉이 캐릭터: 직급·호봉에 따라 진화
- 캐릭터 카드 이미지 저장·복사

### 재방문 유도 요소
- "오늘 번 돈" 실시간 카운터 (초 단위로 올라감)
- 월급날 D-day, 퇴근까지 카운트다운, 다음 공휴일
- 승급·승진·근속 N주년 등 업적 뱃지
- 다음 진화까지 진행률 바

### 이후 (v2+)
- 인사기록·담당 업무·성과 직접 기록 (타임라인)
- 수당·공제 반영한 실수령액 (개인차가 커서 직접 입력 방식)
- 설치형 앱(PWA) / 윈도우 위젯 (Tauri 등, 레인미터 같은 형태) — PoC 이후 검토

## 연가 관리

### MVP
- 연가 사용 기록: 날짜 + 단위(1일 / 반일 / 시간). 입력은 최소 탭으로
- 올해 부여일수는 재직기간으로 자동 계산, 직접 수정 가능
- 잔여 연가 자동 계산
- 달력 뷰에 사용일 표시, 월별 사용 현황

### v2
- 종류 구분: 연가 / 병가 / 공가 / 특별휴가 / 저축연가
- 연가 계획: "예정" 상태, 공휴일과 붙여 쓰는 징검다리 추천
- 연말 소진 알림, 미사용분 연가보상비 예상액
- 저축·이월 처리

### 재미 요소 연결
- 연가를 쓰면 호봉이가 휴가 복장, 오래 안 쓰면 지친 모습
- "올해 연가 소진율" 뱃지

### 주의
- 공식 인사시스템 기록이 기준이며 이 장부는 참고용임을 화면에 명시

## 디자인 컨셉: 픽셀아트
- 전체 UI를 레트로 게임풍으로 (도트 캐릭터, 픽셀 폰트, 상태창 느낌의 대시보드)
- 스프라이트 해상도와 팔레트를 초기에 고정 (예: 48×48, 16색). 정수 배율로만 확대,
  `image-rendering: pixelated`
- 캐릭터는 부품 레이어 조합: 직급 = 기본 형태, 호봉 = 소품·색·이펙트
  → 진화 규칙은 `data/character.json`에 정의, 그림 추가 없이 단계 조정 가능하게
- 픽셀 한글 폰트는 번들에 포함 (외부 호출 금지). 라이선스 확인, 필요 시 서브셋
- 간단한 대기 애니메이션 (2~4프레임), 진화 시 연출
- PoC에서는 직급 2~3단계 + 소품 몇 개로 진화 구조부터 검증

## 반응형·사용성 (데스크톱 + 모바일 웹)
데스크톱과 모바일 웹 모두에서 안정적이고 불편함 없이, 자연스러운 디자인·사용성·조작감으로
동작해야 한다. 한쪽을 줄이거나 늘린 화면이 아니라 각 환경에 맞게 설계할 것.

- 모바일 우선으로 설계 후 데스크톱 확장. 최소 폭 360px부터 대형 모니터까지 깨짐 없이
- 레이아웃: 모바일은 한 열 + 하단 탭, 데스크톱은 여러 열 대시보드로 재배치
- 조작: 터치와 마우스·키보드 모두 1급 지원
  - 터치 대상은 충분히 크게 (최소 44px), 호버에만 의존하는 기능 금지
  - 데스크톱은 키보드만으로 주요 기능 조작 가능, 포커스 표시 명확히
  - 연가 입력·달력은 한 손 엄지로 조작 가능하게
- 입력: 날짜·숫자는 환경에 맞는 입력 방식 사용, 모바일 키보드가 화면을 가려도
  입력란이 보이게 처리
- 픽셀아트는 화면 크기에 따라 정수 배율로만 확대 (흐려짐·찌그러짐 금지).
  본문 글자는 픽셀 폰트라도 작은 화면에서 읽히는 크기 유지
- 반응 속도: 탭·클릭에 즉시 피드백, 애니메이션은 조작을 막지 않게.
  저사양 기기에서도 실시간 카운터가 버벅이지 않게
- 모바일 브라우저 특성 대응: 주소창 높이 변화, 노치·홈 바 안전 영역, 가로·세로 전환,
  실수로 인한 확대·당겨서 새로고침
- 접근성: 충분한 색 대비, 색만으로 정보를 구분하지 않기, 움직임 줄이기 설정 존중
- 파일 저장·불러오기·이미지 복사는 기기별로 동작이 다르므로 각각 확인하고,
  안 되는 환경에서는 대체 방법 제공
- 검증: 주요 화면을 모바일(360·390px)·태블릿·데스크톱 폭에서 직접 띄워 확인.
  Chrome·Edge·Safari(iOS)·삼성 인터넷, 그리고 업무망에서 쓰는 브라우저 버전 기준

## 캐릭터 이미지 저장·복사
- 캐릭터 + 닉네임 + 직급·호봉 + 뱃지를 담은 카드를 canvas에 직접 렌더링
  (화면 캡처 라이브러리 사용하지 않음)
- PNG로 저장 / 클립보드에 이미지 복사 / 모바일은 공유 시트
- 클립보드 복사가 막힌 환경에서는 버튼을 숨기고 저장만 제공 (업무망 file:// 환경 테스트 필요)
- 금액·실명 등 민감 항목은 카드에 기본 미표시, 사용자가 켤 때만 표시
- 카드 하단에 서비스명·주소 표기 (바이럴 유입 경로)
- 메신저 공유용 정사각형과 세로형 두 가지 비율

## 데이터 내려받기·불러오기 (세션 연속성)
사용자가 데이터를 파일로 내려받고, 새 세션(다른 브라우저·PC·망, 저장소 초기화 후)에서
그 파일을 올리면 이전 상태 그대로 이어서 쓸 수 있어야 한다.

- 내려받기: 모든 사용자 데이터를 JSON 파일 하나로 저장
  (입력 정보, 연가 기록, 업적·뱃지, 캐릭터 상태, 설정)
  파일명 예: `hobong-backup-YYYYMMDD.json`
- 불러오기: 첫 화면에 "새로 시작 / 데이터 불러오기"를 나란히 배치.
  파일 선택과 끌어다 놓기 모두 지원
- 파일에 `schemaVersion`, 내보낸 시각, 앱 버전을 포함.
  구버전 파일은 자동 변환(마이그레이션)해 최신 버전에서도 열리게 할 것
- 불러오기 전 검증: 형식이 다르거나 손상된 파일은 기존 데이터를 건드리지 않고 거부,
  이유를 안내
- 기존 데이터가 있을 때는 덮어쓰기 전 확인을 받고, 덮어쓰기 직전 상태를 자동 보관해
  되돌릴 수 있게 할 것
- 파생 값(남은 일수, 금액 등)은 저장하지 않고 불러온 뒤 다시 계산
  → 규정 데이터가 갱신돼도 결과가 최신 기준으로 맞춰짐
- 백업 알림: 마지막 내려받기 이후 변경이 쌓이면 가볍게 알림
  (업무망 PC는 브라우저 저장소가 정책상 지워질 수 있음)
- 파일에 급여·인사 정보가 담기므로 내려받을 때 보관 주의 문구 표시.
  암호 설정 옵션은 v2에서 검토
- 테스트: 내보내기 → 초기화 → 불러오기 후 상태가 완전히 같은지,
  구버전 파일 변환이 되는지 검증

## 기획 발전 과제 (구현 전에 먼저 수행)
이 문서의 기능 목록은 출발점일 뿐이다. 이 프로젝트가 공무원에게 매력적이고 재미있게
와닿도록, 아래를 조사·분석하고 아이디어를 스스로 발전시켜 반영할 것.

1. 수집·분석
   - 공무원들이 실제로 궁금해하고 자주 계산하는 것 (커뮤니티·블로그·기존 계산기 사례)
   - 공무원 사이의 공감 코드, 은어, 밈, 자조 유머
   - 기존 유사 서비스(봉급·퇴직·연가 계산기 등)의 한계와 빈틈
   - 재방문·공유를 잘 만든 서비스의 구조 (육성 게임, 다마고치류, 연말 결산형 콘텐츠,
     유형 테스트, 출석·연속 기록 등)
2. 창발적 발전
   - 위 조사에서 이 문서에 없는 새 기능·연출·문구·세계관 아이디어를 도출
   - 서로 다른 요소를 결합한 아이디어를 우선 (예: 인사 데이터 × 육성 게임 문법)
   - 캐릭터 세계관, 진화 계통, 업적 이름, 화면 문구의 톤까지 포함
3. 산출물과 반영
   - `docs/IDEAS.md`에 아이디어별로 정리: 내용 / 왜 매력적인지 / 구현 난이도 /
     업무망 제약(외부 요청 0건)과의 충돌 여부 / MVP·v2·보류 분류
   - MVP로 분류한 상위 아이디어는 근거를 남기고 바로 구현에 반영.
     무엇을 채택했고 무엇을 미뤘는지 최종 보고에 정리
4. 기준
   - 조사한 사실과 자신의 추론·제안을 구분해 표기
   - 특정 직급·기관·개인을 비하하는 유머, 공직 품위 문제 소지가 있는 표현은 제외
   - 사무실에서 띄워두거나 동료에게 공유해도 민망하지 않은 수준 유지
   - 핵심 설계 원칙(서버 없음, 외부 요청 0건, 개인정보 미수집)을 깨는 아이디어는
     보류로 분류하고 이유를 적을 것
   - MVP 범위를 과도하게 늘리지 말 것. 채택은 효과 대비 구현 부담이 작은 것 위주로

## 근거 법령 (값은 반드시 국가법령정보센터 원문으로 확인 후 입력)
- 국가공무원법: 정년
- 공무원보수규정: 봉급표, 승급
- 공무원수당 등에 관한 규정: 수당, 연가보상비
- 국가공무원 복무규정: 연가일수, 시간 환산, 저축
- 공무원임용령 및 관련 예규: 근속승진, 대우공무원, 승진소요최저연수
※ 기억이나 추정으로 숫자를 넣지 말 것. 확인 못 한 값은 TODO로 남기고 최종 보고에 명시

## 기술 스택 (가정)
- Vite + TypeScript, 프레임워크는 가볍게 (Svelte 또는 바닐라)
- vite-plugin-singlefile로 단일 HTML 빌드 (업무망용)
- Vitest로 계산 로직 테스트
- GitHub Pages 배포

## 주의 사항
- 금액은 "봉급표 기준 추정치"임을 화면에 명시 (실수령액과 다름)
- 실명·소속 등 식별 정보는 입력받지 않음 (닉네임만)
- 휴직·경력 인정·승급 제한 등 예외는 MVP에서 "직접 날짜 입력"으로 우회

## 첫 작업
1. 이 문서를 `docs/PLAN.md`로 저장
2. 기획 발전 과제 수행 → `docs/IDEAS.md` 작성, MVP 채택분을 계획에 반영
3. 프로젝트 초기화, 단일 HTML 빌드 확인
4. `data/2026.json` 스키마 설계 + 법령 원문 확인 후 값 입력

| 진화 몸통 다시 그리기(#29) | 다섯 몸통을 **자세와 동작**으로 구별되게 다시 그렸다: 알봉이(껍데기에 앉음) → 솜봉이(꼿꼿이 섬) → 깃봉이(한쪽 날개를 들어 흔듦) → 날봉이(날개를 활짝 폄) → 봉황(오색 부채깃, 떠오름). 머리(이마 줄무늬·눈·부리·볼)는 다섯 단계가 같은 픽셀이다. 금빛 깃은 새 앵커 `crown` 에 얹어 볏을 가리지 않고, 떠 있는 봉황은 작은 그림자(`shadow-float`)를 쓴다 | 사용자 지적("소품 빼고 다 비슷하다, 멀리서 보면 다 비슷하다"). 성장·깃털과 색·자세 세 방향을 나란히 그려 독립 심사 3명이 골랐다(자세 2표). 12px 실루엣 이웃 단계 겹침(IoU)이 0.88·0.69·0.81·0.70 에서 0.67·0.69·0.71·0.67 로 내려갔다. 몸통은 외곽선으로 닫고 깃·다리는 갈라 두어 2차 꾸미기의 몸 색 바꾸기(영역 판정)가 그대로 먹는다 |

### C. 저장 데이터를 지키는 규칙

| 상황 | 동작 | 까닭 |
|---|---|---|
| 더 새 버전에서 저장한 데이터를 예전 버전(오래된 hobong.html, 열어 둔 옛 탭)이 만남 | 손대지 않고 "새 버전으로 열어 달라"고만 한다. 그 탭은 더 저장하지 않는다 | 업무망에 복사된 파일은 자동으로 갱신되지 않는다. 예전 사본이 새 데이터를 치워 버리면 안 된다 |
| 저장본을 읽지 못함 | 따로 옮겨 두고(처음 것은 덮어쓰지 않음), 옮기는 데 성공했을 때만 원래 자리를 비운다. 첫 화면·설정에서 내려받거나 글자로 볼 수 있다. 나중 버전에서 읽히면 저절로 되살린다 | "말없이 지우지 않는다" |
| 저장본 검사 | 형식·순서만 본다. "오늘"에 따라 달라지는 검사(오늘보다 뒤인 날짜, 최고호봉)는 입력 폼과 파일 불러오기에서만 한다 | PC 시계를 고치거나 규정이 바뀌어도 멀쩡한 데이터가 손상으로 분류되지 않게 |
| 앱이 저장하기 직전 | 다음에 열 때의 검사를 미리 통과하는지 확인하고, 통과하지 못하면 저장하지 않고 알린다 | 앱 스스로 손상을 만들지 않게 |
| 불러오기 | 직전 상태를 보관하지 못하면 불러오지 않는다. 되살린 상태를 저장하지 못하면 보관본을 지우지 않는다 | 되돌릴 길 없이 바뀌지 않게 |
| 내려받기 | 파일 안의 "마지막 내려받기"·백업 배지를 내려받은 뒤의 상태로 맞춘다. 브라우저가 저장 완료를 알려 주지 않으므로 "파일이 생겼는지 확인해 달라"고 한다 | 내보내기 → 초기화 → 불러오기 뒤 상태가 완전히 같게 |
| 다른 페이지 안(iframe) | 열리지 않고 안내만 보인다 | 겹쳐 보이게 해 누르게 만드는 속임수 방지(메타 태그 CSP로는 frame-ancestors를 줄 수 없다) |
| 페이지 이동·새 창 | 코드에 없어야 빌드가 통과한다(빌드 후 검사) | CSP는 하위 리소스 요청만 막고 최상위 이동은 막지 못한다 |
| 저장본의 계급이 그 해 규정 데이터의 사다리에 없음(데이터 변경·T1 군무원처럼 사다리가 나중에 생김) | 열고, 상태창에서 "계급을 (다시) 골라 주세요"와 [내 정보 고치기]. 봉급·계급정년은 '준비 중' | 저장본 검사는 형식만 본다(일반직만 코드 상수 '1'~'9'). 규정 데이터가 늘어도 멀쩡한 저장본이 거부되지 않게 |
| 저장본의 꾸미기 id(`character.look`)·배경음악 곡 id·직렬이 지금 목록에 없음(v5) | 거부하지 않고 그대로 보존한다(형식만 본다). 그릴 때·틀 때만 기본값으로 대신하고, 직렬은 이름을 보이지 않는다 | 꾸미기·곡 목록은 같은 저장 형식 버전에서도 늘어난다. 예전 사본이 새 장식 id 하나 때문에 백업 전체를 거부하지 않게. 직종(`track`)은 계산 키라 목록 밖이면 거부한다 |
| 다른 탭이 데이터를 바꿈 | storage 이벤트로 따라가고, 이벤트가 오지 않아도 탭으로 돌아올 때(포커스·다시 보임) 저장소를 다시 본다. **쓰기 직전마다** 저장소의 원문이 이 탭이 마지막으로 읽거나 쓴 값과 같은지 보고, 다르면 쓰지 않고 그 값을 따라간다(부록 J) | WebKit(Safari 엔진)은 새로 고친 탭에 다른 탭의 storage 이벤트를 보내지 않는다(CI에서 확인). 같은 탭의 쓰기에는 이벤트가 오지 않는다 |

**알려진 한계**
- 파일(hobong.html)로 열어 쓰면 Chrome·Edge에서는 같은 PC의 다른 로컬 HTML 파일과 브라우저 저장소를 함께 쓴다. 다른 HTML이 그 값을 읽을 수 있다. 화면·README에 알린다. 내려받는 백업 파일에는 암호를 걸 수 있지만(#13), 브라우저 저장소 자체는 암호화하지 않는다.
- 브라우저는 파일 저장이 끝났는지 페이지에 알려 주지 않는다. 메신저 앱 안 브라우저처럼 내려받기를 조용히 무시하는 환경은 실제 기기에서 확인하지 못했다.

### D. 검증 범위

- 자동: 단위 테스트(계산·규정 데이터·저장·캐릭터·업적·글꼴 형식·문구), 종단 테스트(Chromium 데스크톱 1280px·모바일 360px,
  CI에서는 Firefox·WebKit도). 폭 320~1920px에서 넘침·겹침·44px 미만 터치 대상(실제 누르는 영역)을 검사한다.
- 화면 검수: 실제 앱을 폭·테마(밝은·어두운·고대비)·데이터 조건별로 찍어 영역별 검수자가 보고, 재현으로 확정한 것만 고친 뒤
  독립 확인했다(2026-11-26, 확정 55건).
- 글꼴: WOFF2 의 glyf 변환을 하면 WebKit 이 큰 글꼴을 해독하지 못해(대체 글꼴로 그려짐) 변환 없이 저장한다.
  종단 테스트는 글꼴 API 의 보고 대신 실제로 그려진 글자 폭으로 픽셀 글꼴이 쓰이는지 본다.
- 직접 확인하지 못한 것: 실제 iOS Safari·삼성 인터넷 기기, 업무망의 구형 브라우저. CI의 WebKit·Firefox는
  엔진만 같을 뿐 실제 기기를 대신하지 못한다. 이 부분은 이슈로 남겨 두었다.

### E. 대상 확대(#20) 결정 기록

**'준비 중' 원칙.** 원문으로 확인한 규정만 계산한다. 확인하지 못한 항목은 일반직 값으로 대신하지 않고,
숫자 없이 '준비 중'(원문 미확인)·'해당 없음'(그 직종에 없음)·'다른 기준'(조례·기관 기준)과 사유를 화면마다 같은
모양(꼬리표 + 사유 한 줄)으로 보인다. 준비 중이 있는 직종은 홈에 "○○는 일부만 계산해요. 준비 중: …" 띠를 한 번
띄우고 근거 법령 화면의 그 직종 칸으로 이어 준다. 금액은 모두 '봉급표 기준 추정치'다.

| # | 질문 | 결정 |
|---|---|---|
| Q1 | 계급정년 '이른 날' | 현 계급 임용일의 N년 **기념일** + 1/1·7/1 주의 문구 + 직접 고치기 칸 |
| Q2 | 카드에 계급 이름 | `card.showRank` 를 둔다. **일반직 사다리(1~9급)만 기본 켬**, 경찰·소방·우정·외무는 끔(계급 이름이 직종·직렬을 드러낸다). 첫 입력과 직종을 바꿀 때 맞추고 띠로 알린다. v3 사용자는 켬(카드 그대로). 캐릭터·결산 카드가 모두 따른다 |
| Q3 | 교원 진화 기준 | 재직 연수 0·2·5·10·20년(`data/character.json`) |
| Q4 | 준비 중 직종 | **확인한 것만 계산하고 나머지는 '준비 중'(숫자 없음).** '일반직 기준으로 둘러보기'는 두지 않는다 |
| Q5 | 치안총감·소방총감 | 별표 10 에 열이 없어 **고를 수 없게** 하고 계급 칸 아래에 그 까닭을 적는다 |
| Q6 | 교육전문직원(장학사 등) | 교원 직종에 안내 한 줄(휴가는 복무규정, 연가보상비를 받을 수 있음) |
| Q7 | 소방 장기재직휴가 | 숫자 없이 조례 안내(시·도 소속은 조례, 소방청 소속은 복무규정) |
| Q8 | 묶음 1 에서 더 확인할 원문 | T4·T5·T8 만. T4(해양경찰 연가)·T5(우정 상당 계급)는 넣었고 T8(교원 시보)은 원문으로 정할 수 없어 준비 중 |
| Q9 | 직렬 저장 | 저장하지 않음(B 표 '직렬') |
| Q10 | v4 동안 홈의 계급 이름 | 홈에는 늘 보인다(본인 화면, 상태창의 중심 정보). 공개 설정은 2차 v5 의 `showSeriesHome` 에서. 대신 첫 화면과 카드 설정에 '홈 화면에는 계급 이름이 보여요'를 적는다 |
| Q11 | 교사 직급보조비 | `external`(별표 15 비고 제8호: 인사혁신처장이 정한다). 계산하지 않는다 |
| Q12 | 2차 첫 입력의 직종 질문 | **필수**(건너뛰면 일반직 숫자가 다른 직종에 보인다). 지금 입력 폼에서도 직종은 늘 고른 상태(기본 일반직)다 |

화면에 넣은 그 밖의 규칙: 직종 칩 글자에 '(준비 중)'·'(일부 준비 중)'을 붙인다(색만으로 구별하지 않는다).
직종·봉급표를 바꿔 지금 계급이 새 사다리에 없으면 가장 낮은 계급으로 맞추고 한 번 낭독한다. 별표 4 를 고르면
'별표 4는 누가 쓰나요?'에 별표 1 원문과 '특정직은 그 밖의 특정직을' 안내를 둔다. 별표 4 + 4급 이상은 '직접 종사'
경고. 직종 이름 뒤 조사는 받침으로 고르고(`josa()`), 화면 코드에 숫자 뒤 '급'을 붙여 계급 이름을 만드는 곳이
없음을 테스트가 본다.

### F. 나만의 호봉이(2차 A: #17 꾸미기·#16 직렬 소품) 결정 기록

| # | 질문 | 결정 |
|---|---|---|
| F1 | 꾸미기를 어디서 | 설정의 '호봉이 꾸미기' 창 → 고르는 대화상자. 고르는 동안은 저장하지 않고 '바꾸기'를 눌러야 저장한다('취소'는 버린다). 첫 입력의 '호봉이 고르기' 단계는 같은 고르기 칸(`LookEditor`)을 2차 B 에서 쓴다 |
| F2 | 고르는 칸 | 몸 색 8·볏 5·깃 6('알아서' 포함)·머리핀·가슴 배지·볼 터치·손 소품(직렬 따라 — 특정직은 '호봉 따라'·들지 않기·18종). 견본은 모두 진짜 라디오(묶음마다 Tab 하나, 방향키로 고름), 견본마다 이름 글자, 고른 견본은 두꺼운 테두리 + ✓(색만으로 구별하지 않음), 키보드 포커스는 그 바깥에 틈을 둔 잉크색 점선(모양·색이 다르다), 44px 이상, 고대비에서는 시스템 색 테두리. 장식 견본(핀·배지·볼 터치)은 그 자리만 잘라 3배로 그린다. 견본 칸은 4열(넓은 화면 8열). 좁은 폭에서는 미리보기 줄이 대화상자 위에 붙고, 900px 이상에서는 대화상자를 넓혀 미리보기를 왼쪽 열에 고정한다 |

'준비 중' 한마디와 호봉 알리기는 받은 뒤에만 보인다. 닫으면 다시 나오지 않는다. [나중에]를 누르면 다시 묻지 않고(설정 위치를 알림), 그 뒤 권유는 기존 안내 띠의 문턱을 따른다. 아직 고르지 않았으면 새로 고친 뒤에도 남는다. 예전부터 쓰던 사람·패키지로 이어 온 사람에게는 띄우지 않는다. |
| H16 | 로그인·정보 저장을 어떻게 말하나 | 패키지를 받거나 불러오는 자리(홈 안내 창·설정의 패키지 창·불러오기 창)에 '준비 중'이라는 한마디(`talk.json` 의 `wit`, 변형 셋)를 둔다. **약속이 아니므로 기한·날짜를 말하지 않는다**(테스트가 숫자·'곧'·'예정' 같은 낱말을 막는다). 서버가 없다는 사실과 어긋나지 않게 '그때까지는 파일 하나면 충분해요'로 맺는다 |
| H17 | 알리기(공유) | '호봉 알리기'는 **사이트 주소만** 전한다: 공유 시트(Web Share)가 있으면 정해진 제목·소개 글·주소, 없으면 주소를 클립보드에 복사한다. 닉네임·입력값·계산값은 싣지 않고(소개 글에 자리표시자가 없음을 테스트가 본다), 앱이 어디로도 직접 보내지 않는다. 소개 글에 '개인이 만든 비공식 도구'라고 적는다(공식 기관처럼 보이지 않게) 권유 문장은 변형 셋(`share.leads`)이고 '준비 중' 한마디와 같은 차례로 짝을 이뤄 이어 읽힌다(이삿짐 → '이삿짐을 다 쌌으면 옆자리 알도 깨워 주세요'). **권유는 써 본 뒤의 자리에만**: 패키지를 받은 뒤(홈 안내)·설정·카드 화면('카드 대신 사이트 주소만'). 첫 화면에서도 열리는 불러오기 창에는 한마디만 두고 알리기는 권하지 않는다. 패키지 안내의 '3초 만에' 같은 실제와 다른 숫자는 쓰지 않는다('질문 없이 바로') |
| H19 | 첫 입력 중 뒤로 가기·새로 고침 | 대화·폼에 들어서면 기록(`history.pushState`, 주소는 그대로)에 자리 하나를 끼운다. 브라우저의 뒤로 가기(안드로이드 버튼·제스처)는 사이트를 떠나지 않고 **이전 질문**(인사·폼에서는 첫 화면, 대화상자가 열려 있으면 그것부터 닫음)으로 가고, 첫 화면에 닿거나 저장을 마치면 끼운 자리를 거둔다(뒤로 가기가 헛돌지 않게). 넣은 값이 있는데 아직 깨우지 않았으면 새로 고침·창 닫기 전에 브라우저가 한 번 묻는다(`beforeunload`, 저장 뒤 해제). **초안은 여전히 어디에도 저장하지 않는다**('반쯤 저장하지 않는다' 원칙 — 세션 저장소에 초안을 두는 일은 하지 않았다) 대신 인사말이 '알을 깨울 때 저장돼요(그 전에 창을 닫으면 사라져요)'라고 미리 알린다(검토에서 세션 저장소에 초안을 두는 안이 다시 나왔으나 이 결정을 유지했다 — 탭이 다시 불려 와 답이 사라지는 불편은 남는다. 바꾸려면 생년월일 같은 값을 깨우기 전에 저장소에 두는 일을 사용자에게 어떻게 알릴지부터 정해야 한다) |
| H20 | 확인 화면·호봉 칸 | [알 깨우기]는 확인 화면 아래에 붙어 있다(`position: sticky` — 답 목록이 길어도 빛나는 알과 함께 늘 보인다). 호봉 칸(`Stepper`)은 들어서면 든 숫자를 모두 고른다(기본값 '1'에 9를 쳐 '19'가 되는 일을 막는다) |
| H18 | 테스트 바탕 | e2e 의 `helpers.onboard()` 는 '새로 시작 → 한 번에 쓰기 → 알 깨우기 → 건너뛰기 → 바로 시작하기'. 대화 흐름은 `talk.spec`, 패키지 안내·이어하기·알리기는 `package.spec`, 연출은 `growth.spec`. `playwright.config.ts` 의 모바일 프로젝트 대상에 `talk.spec` 을 더했다(화면 키보드·좁은 폭 검증이라 모바일에서도 돈다 — 검증이 늘었을 뿐 느슨해지지 않는다) |

### I. 생애 봉급(#30) 결정 기록

사용자 요청: "남은 임기와 앞으로 정년까지 몇 번 월급을 받는지, 정년까지 다닌다면(혹은 퇴직일을 지정할 수 있게 해서)
내 생애소득은 총 얼마 중에 지금까지 얼마를 벌었는지 등을 볼 수 있는 기능". 두 묶음으로 나눠 만들었다 —
**묶음 1**(계산과 홈 창, 정년 기준, 저장 형식 변화 없음: I1~I18)과 **묶음 2**(퇴직 예정 달, 저장 형식 v6: I19~I30).

| # | 질문 | 결정 |
|---|---|---|
| I1 | 이름 | 홈의 새 창 **'생애 봉급'**, 큰 숫자는 **'생애 봉급(추정)'**. 봉급만 세므로 '소득'·'연봉'·'수입'이라고 부르지 않는다(테스트가 막는다). 요청의 '생애소득'은 수당·세금·퇴직급여를 모르는 이 서비스가 답할 수 없는 이름이다 |
| I2 | 금액의 범위(조정자 Q2) | **봉급만.** 정근수당은 금액 없이 **횟수**만, 명절휴가비는 세지 않는다(그 해 달력이 없으면 설날·추석 날짜를 모른다). 일부 수당만 더하면 '지금까지 + 앞으로 = 총액'과 지갑 창 숫자의 일치가 깨진다 |

### J. 다른 탭이 바꾼 저장본을 덮어쓰지 않기(#26) 결정 기록

CI 의 WebKit(mobile-safari)에서 `responsive.spec.ts` '360px: 닫을 수 있는 안내 띠…'가 두 번 연속 실패했다(커밋 6c7f2d9).
테스트가 시계를 다시 맞추고(날짜가 바뀜) 새 저장본을 넣은 뒤 새로 고치기 전에, 떠 있던 옛 페이지의 시계가 날짜 바뀜을 보고
방문을 기록하면서(`recordVisit` → `commit` → `#persist`) **옛 메모리 데이터를 저장소에 썼다**. `#persist` 는 더 새 형식 버전인지만
봤고, 저장소가 바뀌었는지(`#lastRaw`)는 포커스·다시 보임에서만 봤다. 실사용에서는 배경에 떠 있던 탭 A 가 자정의 방문 기록·업적·
도감·승급 확인을 저장하면서 탭 B(또는 다른 hobong.html 사본)의 변경을 지우는 버그다. 테스트가 아니라 앱을 고쳤다(`openApp` 은 그대로).

| # | 질문 | 결정 |
|---|---|---|
| J1 | 어디서 막나 | `#persist` 가 쓰기 직전마다 저장소의 지금 원문을 읽어 `#lastRaw`(이 탭이 마지막으로 읽거나 쓴 값)와 견준다(`#inSync`). 다르면 **쓰지 않고** `#followOtherTab` 과 같은 길로 저장소의 값을 따라간다. 저장의 결과는 `'saved' \| 'unsaved' \| 'discarded'`(`SaveOutcome`), `commit` 은 썼는지(boolean)를 돌려준다. 저장 형식(v6)은 그대로다 |
| J2 | 왜 '이 탭의 변경을 다시 얹지' 않나 | 화면의 동작은 옛 데이터를 보고 만든 것이다(내 정보 폼은 프로필 전체를, 꾸미기는 모습 전체를 쓴다). 따라간 값 위에 그대로 얹으면 다른 탭의 변경을 말없이 지우는 같은 버그가 된다. 자동 기록은 화면의 effect 가 따라간 값으로 다시 부르므로 따로 얹지 않는다. 예외는 행동 배지(`grantEvent`) — 더하기만 하는 기록이라 따라간 값 위에 한 번 더 준다 |
| J3 | 알리기 | 사용자가 방금 한 것(연가 기록·지우기, 부여 일수, 내 정보, 설정, 꾸미기, 정한 달, 되돌리기, 모두 지우기)을 버렸으면 기존 알림(토스트, `warn`, 12초 — J13)으로 "다른 탭(또는 다른 hobong.html)에서 데이터가 바뀌어 방금 한 것은 저장하지 않았어요. 바뀐 내용을 불러왔으니 다시 해 주세요." 화면은 '기록했어요'·'고쳤어요'·'정했어요' 같은 말을 하지 않는다. 자동 기록(방문·업적·도감·승급 확인·백업 표시)은 조용히 따라간다. 새 알림 체계는 만들지 않았다 |
| J4 | 호출부 | 대화상자(내 정보 고치기·꾸미기·부여 일수·여러 날 한꺼번에·생애 봉급 폼)는 버려져도 닫는다 — 폼은 옛 값으로 채워져 있으니 다시 열어 바뀐 데이터로 시작하게 한다. 연 뒤 저장 순간보다 먼저 따라갔을 때도 같다(J13 ①). 연가 한 건 기록은 메모를 남겨 다시 누르면 되게 한다. 승진 연출·직종 안내(`trackChange`)·복귀 정산(`welcomeBack`)은 버린 쓰기로 만들지 않는다. 버린 업적 기록은 배지를 알리지 않는다(따라간 값으로 다시 셈해 두 번 알리지 않게). 야근 모드 배지는 테마가 바뀌었을 때만 준다. 정한 달은 같은 값을 다시 골라도 저장소가 바뀌었으면 '정했어요'라고 하지 않는다(`setRetirePlan` → `'discarded'`) |
| J5 | 첫 입력(알 깨우기) | 첫 화면을 여는 동안 다른 탭이 먼저 내 정보를 넣었으면 그 데이터를 불러오고 알을 깨우지 않는다("…먼저 내 정보를 넣어서 그 데이터를 불러왔어요. 방금 넣은 내용은 저장하지 않았어요. 다르면 설정에서 고쳐 주세요."). 저장소가 비어 있으면(다른 탭이 지웠어도) 지킬 것이 없으므로 그대로 만든다. 저장할 수 없을 때의 알림은 `Welcome` 이 아니라 `createProfile` 이 띄운다(두 번 뜨지 않게) |
| J6 | 다른 탭이 지웠을 때(저장소가 빔) | `#followOtherTab` 의 규칙 그대로 첫 화면으로 간다. 지운 데이터에 딸린 이 탭의 연출·복귀 정산·직종 안내·부화·차례 등장도 거둔다(연출이 남아 있으면 알림이 계속 미뤄진다). 사용자가 한 것이었으면 "…데이터를 모두 지워서 방금 한 것은 저장하지 않았어요. 처음부터 넣거나 임용정보 패키지로 이어해 주세요." |
| J7 | 읽지 못할 값·더 새 버전으로 바꿨을 때 | 저장소를 건드리지 않는다(옮기지도 지우지도 않는다). 이 탭은 `staleNotice` 띠("새로 고침")를 띄우고 더 쓰지 않는다. 바뀐 내용은 이 탭의 메모리에만 남으므로 결과는 `'unsaved'`(정한 달 창은 "저장하지 못했어요"). '다시 해 주세요'는 하지 않는다(다시 해도 저장되지 않는다). 이 상태에서는 **모두 지우기도 하지 않는다** — 예전 사본이 새 데이터를 치우지 않게(부록 C 첫 줄) |
| J8 | 불러오기(임용정보 패키지) | 버리지 않는다. 먼저 저장소의 값을 따라가고, 그것을 되돌리기 보관본으로 둔 뒤 불러온다. 사용자가 고른 파일로 어차피 바꾸는 것이고 다른 탭의 변경은 보관본에 남아 되돌릴 수 있다. 되돌리기는 반대로 보관본으로 덮는 것이라 그 사이 바뀌었으면 버리고 알린다(알고 나서 다시 누르면 되돌린다) |
| J9 | 거짓 경보 막기 | 이 탭이 쓴 뒤에는 늘 `#rememberStored()`. 열 때 저장본을 바꾸거나(v1~v5 → v6) 따로 옮겨 둔 저장본을 되살리면 읽은 직후 저장소의 값을 먼저 기억한 뒤 저장한다. 되돌리기 보관(`hobong.undo`)·읽지 못한 저장본 보관(`hobong.corrupt`)은 데이터 칸이 아니라 견주지 않는다. 모두 지운 뒤에는 빈 값을 기억한다. 저장소가 막힌 브라우저(사생활 보호 창)는 메모리 저장소라 늘 같고, 가득 찬 저장소는 쓰기만 실패해 원문이 그대로라 다른 탭 탓으로 보지 않는다. 저장소를 읽을 수 없으면 견주지 않고 예전처럼 쓴다(실패하면 `saveFailed`). 단위 테스트가 이 경우들을 하나씩 본다 |
| J10 | 따라가면 `saveFailed` 를 내린다 | 저장소의 값을 읽어 따라갔으면 이 탭의 메모리와 저장소가 같으므로 '방금 바꾼 내용을 저장하지 못했어요' 띠를 내린다(storage 이벤트로 따라갈 때도 같다) |
| J11 | 재현 테스트 | Chromium 만 있는 기기에서 WebKit 의 순서를 결정적으로 되풀이한다: 페이지가 떠 있는 채로 페이지 스크립트로 저장소를 바꾸고(같은 탭의 쓰기라 storage 이벤트가 오지 않는다), 시계를 다음 날로 돌려 방문 기록을 일으키거나 사용자가 무언가를 바꾼 뒤 저장소를 본다(`tests/e2e/tab-sync.spec.ts`, `openApp` 을 이어 부르는 차례 포함). 단위 테스트는 가짜 저장소로 `AppStore` 를 열고 바깥에서 저장소를 바꾼다(`tests/unit/tab-sync.test.ts`, `newAppStore`). 둘 다 고치기 전에 실패하는 것을 확인했다 |
| J12 | 남은 한계 | 견주는 것은 쓰기 직전의 한 번이다. 두 탭이 같은 순간(같은 밀리초 근처)에 쓰는 경우는 막지 못한다(localStorage 에는 비교 후 쓰기가 없다). Firefox·WebKit 에서의 동작은 CI 에서만 확인한다. 첫 입력 중에 다른 탭이 먼저 넣었을 때 '방금 넣은 것으로 바꾸기'를 고르게 하지는 않았다(J13 ⑤ — 알리고 따라가기만 한다). 첫 입력 중에 따라가면 새 배지 알림이 두 번 뜰 수 있다(고치기 전부터 있던 것, 데이터와는 무관) |
| J13 | 독립 검증 셋의 지적 반영 | ① **대화상자를 연 뒤 먼저 따라갔을 때**: storage 이벤트·포커스·다시 보임으로 저장 순간보다 먼저 따라가면 `#inSync` 는 통과해 옛 초안(내 정보 전체·모습 전체)이 다른 탭의 변경을 말없이 덮었다(고치기 전부터 있던 길). `AppStore.dataGeneration` 이 따라갈 때마다(데이터 칸 원문이 바뀌었을 때만) 오르고, 초안을 든 대화상자(내 정보 고치기·꾸미기·부여 일수·정한 달)는 열 때 그 값을 기억해 `updateProfile`·`updateLook`·`setGrantOverride`·`setRetirePlan` 에 `base` 로 넘긴다. 다르면 저장 순간에 알게 된 것과 똑같이 버리고 알린다. 여러 날 한꺼번에는 고를 날을 지금 데이터에서 다시 세고 더하기만 하므로 넘기지 않는다. 바로 저장하는 스위치·칸은 초안이 없으니 넘기지 않는다 ② **버려진 뒤의 스위치·칸**: `checked={…}`·`value={…}` 는 한쪽으로만 묶여, 따라간 값이 누르기 전과 같으면 다시 그려지지 않아 누른 모습이 남았다(금액 가리기가 켜져 보이는데 금액이 보이고, '다시 해 주세요'대로 누르면 반대 값이 저장됐다 — 이 수정이 들여온 문제). `updateSettings` 가 false 면 그 요소를 지금 저장값으로 되돌린다(설정의 스위치·근무시간·직접 넣는 월급날, 카드의 스위치). 칩(ChipRadio)은 값에서 다시 그려 맞다 ③ **지운 연가 되살리기**: [되돌리기]는 눌리면 사라져 '다시 해 주세요'라고 하면 기록과 메모를 잃는다. id 가 없을 때만 넣는 기록이라 버려지면 따라간 값 위에 한 번 더 한다(`grantEvent` 와 같다. J2 의 예외). 지운 뒤 추가를 되돌리는 쪽(`removeLeave`)은 지금 문구 그대로 ④ **버렸다는 알림**: 12초 두고, 사용자의 다음 저장이 되면 바로 닫는다(두 말이 나란히 남지 않게) ⑤ **첫 입력**: 알 깨우기가 막혔을 때와 storage 이벤트·포커스로 첫 화면에서 끌려 나왔을 때 같은 말을 한다 — 불러온 닉네임을 넣어("…그 데이터(닉네임 '…')를 불러왔어요."), 넣던 것이 있었으면 "방금 넣은 내용은 저장하지 않았어요."를 붙인다. 끼워 둔 기록 자리를 거두고(홈에서 첫 [뒤로]가 헛돌지 않게), 포커스를 홈 본문(`#main`)으로 옮긴다. Svelte 5 의 정리 함수는 바뀌기 전 값을 읽으므로 `app.data` 는 한 박자 뒤에 본다 ⑥ **이 기기 편의 값(hobong.prefs)**: 쓰기 직전마다 저장소를 다시 읽어 바꿀 칸만 얹는다(다른 탭이 'done' 으로 바꾼 패키지 안내를 이 탭의 옛 'pending' 위에 '나중에'로 덮지 않게). storage 이벤트로도 따라간다 ⑦ **문구 둘**: 다른 탭이 이미 모두 지웠으면 모두 지우기는 바라던 대로 된 것이라 지웠다고 한다. 이 탭이 더 쓰지 않는 상태의 되돌리기는 '되돌릴 수 있는 상태가 없어요'가 아니라 "지금은 저장할 수 없어요. 새로 고친 뒤 다시 해 주세요."(`undoImport` → `'blocked'`) ⑧ **테스트 작성 규칙**: 한 테스트 안에서 날짜를 바꿔 같은 문서로 다시 열면(해시만 바뀌는 `openApp`) 옛 페이지가 새 저장본을 따라간 뒤 그 위에 방문·업적·도감·승급 확인을 기록한다. 처음 열 때 한 번만 생기는 것(복귀 정산·승급 연출·새 배지 알림·v3 띠)을 보려면 새 페이지(`context.newPage()`)로 연다(`tests/e2e/helpers.ts` 의 `openApp` 주석). 앱은 그대로다 — 다른 탭이 이미 기록한 방문을 다시 정산하지 않는 것이 맞다. 회귀는 `tests/unit/tab-sync.test.ts`·`tests/e2e/tab-sync.spec.ts` |

### K. 교육행정·지방 일반직(#31) 결정 기록

요청: "직렬 선택 시 교육행정 선택이 없는 거 개선해". 국가 직렬표(공무원임용령 별표 1)에서 교육행정은 **행정 직렬의 직류**라 목록에

### M. 직렬 찾기를 사람 말로(#38) 결정 기록

요청: "경찰행정 직렬도 없다." (앞선 요청 "직렬 선택 시 교육행정 선택이 없는 거 개선해" → 부록 K). 같은 종류의 두 번째 지적이라
이름 하나를 더하지 않고, 법령 표의 이름과 사람들이 부르는 이름이 다를 때 생기는 막힘을 통째로 없앤다. 설계 원문은
`docs/research/series-renames/design.md`. 자료의 뜻과 근거는 `docs/DATA.md` '넓게 찾기와 찾기 사전'·'직접 적은 이름'.

| # | 질문 | 결정 |
|---|---|---|
| M1 | 찾기를 어떻게 넓히나 | 지금 찾기(`searchSeries`, R0)를 그대로 먼저 돌리고, 두 표 어디에서도 못 찾았을 때만 꾸밈말 떼기(R1) → 줄임말(R1') → 조각(R2)을 차례로(`findSeries`). 표에 실제로 있는 이름이 늘 먼저다. `searchSeries` 와 그 테스트의 기대는 하나도 바꾸지 않았다 |
| M2 | 조각 찾기 | '경찰행정' → 행정처럼 찾는 글자 안의 표 이름을 권하되 **짐작**으로 표시한다: 상태 줄에 '이름에 든 글자로 찾았어요', Enter 로 저절로 고르지 않음. 설계와 달리 R1 까지 **다른 표**에서 찾았으면 조각 찾기를 하지 않는다(R0 에서 다른 표에만 있을 때와 같게 — 다른 표 안내가 답이다. '보건진료직'을 국가 표에서 찾을 때 '보건'을 권하지 않는다) |
| M3 | 줄임말 | 공무원 사이에서 굳은 셋(`교행`·`일행`·`사복`)만 `series.json` `finder.short` 에 두고, 화면에 '줄임말'이라고 밝힌다. 부록 K9(COORD)의 '줄임말 찾기 없음'을 뒤집었다: 사용자가 같은 종류의 막힘을 두 번째로 지적했고, 사전이 저장 키가 아니라 원문 이름으로 이어 주기만 하며(고르면 원문 이름이 저장된다), 셋으로 묶고 데이터 테스트(`say` 는 표에 없는 이름, `means` 는 표의 이름)로 지켜 '법령에 없는 이름이 법령의 이름처럼 보이는' 일이 생기지 않기 때문이다 |
| M4 | 흔히 부르는 이름 | 근거가 있는 것만 `finder.common` 에(지금 `경찰행정` 하나, 근거는 DATA.md). 설명은 '흔히 … 이렇게 불러요. 인사기록에 적힌 직렬 이름으로 골라 주세요.' — 법령의 직렬이 아니라고 밝히고 표의 이름으로 이끈다. 경찰청 소속 일반직은 별표 4 대상에 적혀 있지 않아 봉급표 안내는 하지 않는다 |
| M5 | 직종 말 | 찾는 글자에 다른 직종 이름(규정 데이터의 label)이 들면 '직종에 경찰이 따로 있어요. 해당하면 직종을 바꿔 주세요. 그 직종은 직렬을 고르지 않아요.' 직종을 **저절로 바꾸지 않는다**([직종 고르기로 가기]만). 지금 직종·직렬 표가 있는 직종은 빼고, 겹치면 긴 이름만, 지금 표에서 이름이 같게 찾으면 숨긴다. 직종 id 로 가르지 않는다(label 과 `seriesScope` 만 본다 — 테스트) |
| M6 | 직접 적기와 저장 형식 | **저장 형식(v7)·검사·변환은 그대로.** 새 칸 없이 '두 표 어디에도 없는 이름(옛 이름 포함, 형식·12자)'을 직접 적은 이름으로 정의했다. 다른 표에만 있는 이름은 지금처럼 숨기고 짝을 권한다. 결과로 예전에 '목록에 없는 저장값'으로 숨던 두 표 밖의 이름도 보이게 됐다(e2e `customize.spec` 의 '없는직렬' 기대를 '(직접 적은 이름)'으로 고쳤다) |
