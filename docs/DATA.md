# 규정 데이터 갱신 가이드

호봉의 숫자(봉급표, 연가 일수, 승진 요건, 공휴일…)는 코드가 아니라 `data/<연도>.json` 에 있다.
법령이 바뀌면 **이 파일만** 고치면 되고, 화면의 "근거 법령"도 여기서 읽어 보여준다.

## 원칙

1. **원문에서 확인한 값만 넣는다.** 기억, 기사, 블로그, 추정으로 숫자를 넣지 않는다.
   기준은 [국가법령정보센터](https://www.law.go.kr)의 현행 법령 원문이다.
2. **값마다 근거를 적는다.** 법령·조항·개정일(`source`)과, 확인한 법령 판본(`laws`).
3. **확인하지 못한 값은 넣지 않는다.** 그 항목을 `pending` 에 적어 두면 앱은 이전 연도 값으로
   계산하면서 화면에 "○○년 표 기준(확정 전)"이라고 밝힌다. 틀린 숫자를 조용히 보여주지 않는다.
4. **발췌본을 남긴다.** 확인한 원문을 `docs/sources/<연도>/` 에 글자 그대로 저장한다.
   테스트가 데이터와 발췌본을 대조한다.

## 파일 구성

```
data/
  2026.json        그 해에 적용할 규정 전체 (status: verified)
  2027.json        2026을 이어 쓰고(extends) 달라진 항목만 담는다
  character.json   캐릭터 진화 규칙과 꾸미기(custom) (법령과 무관)
  series.json      직렬·직류 → 호봉이 소품 테마 (국가: 공무원임용령 별표 1·2, 지방: 지방공무원 임용령 별표 1)
  lines.json       호봉이의 한마디 (법령과 무관)
docs/sources/<연도>/   원문 발췌본
```

```jsonc
{
  "schema": 1,
  "year": 2027,
  "extends": 2026,            // 이 파일에 없는 항목은 2026년 값을 쓴다 (항목 단위, 깊은 병합 아님)
  "target": { "id": "national", "label": "국가공무원" },  // 모든 연도 파일이 같아야 한다(테스트)
  "status": "partial",        // verified: 전 항목 확인 / partial: 일부만 확정
  "verifiedAt": "2026-11-25", // 원문을 마지막으로 확인한 날
  "pending": ["salary", "payTables"], // 아직 확정 전이라 이전 연도 값을 쓰는 항목
  "notes": ["…"],
  "laws": {                   // 확인한 법령 판본
    "pay": {
      "name": "공무원보수규정",
      "effective": "2026-10-02",
      "promulgation": "대통령령 제36728호, 2026. 9. 29., 타법개정",
      "url": "https://www.law.go.kr/법령/공무원보수규정"
    }
  },
  "salary": {
    "table": { "9": [2133000, 2147600, …], "8": […] },  // 직급 → 1호봉부터
    "source": {
      "law": "pay",                          // laws 의 키
      "article": "제5조, 별표 3",
      "revised": "2026-01-02",               // 그 조항·별표의 개정일
      "snapshot": "pay-reg-table3-salary.txt", // docs/sources/<연도>/ 아래 발췌본
      "note": "해석, 반영하지 않은 예외"
    }
  }
}
```

항목(섹션)은 **열세 개**다. 일반직 기본 구역 열한 개 — `retirement` `probation` `salary` `stepRaise`
`promotionStep` `payday` `workHours` `leave` `promotion` `allowances` `holidays` — 와 직종 확대 구역 두 개
— `payTables` `tracks` — 이고(코드의 `RULE_SECTION_KEYS`), 형식은 `src/lib/rules/types.ts` 에 있다.
어느 해든 `extends` 를 따라가 열세 개가 모두 채워져야 한다.

- 기본 구역 열한 개는 **일반직(별표 3) 값**이다. 다른 직종은 이 값을 그대로 쓰지 않는다(아래 "직종을
  더하거나 고칠 때").
- `payTables` 는 별표 4·8·10·11 봉급표다. 별표 3 은 지금처럼 `salary` 에 있다. 다른 구역과 달리
  **표(`items` 의 키) 단위**로 합친다 — 개정 봉급표가 나왔을 때 바뀐 표만 넣으면 나머지는 이전 해 표를
  쓰고, 그 표가 어느 해 것인지는 `meta.payTableYear` 에 남는다.
  표에 `longServiceAddOn`(근속가봉: 금액 `amount`, 가산 횟수 상한 `maxCount`, 근거 `source`)을 둘 수 있다 —
  공무원보수규정 제30조의2 에 **금액이 정해진 봉급표에만** 넣는다(지금은 별표 11 하나). 봉급 계산에는 쓰지 않고,
  '생애 봉급' 창이 그 표의 사용자에게만 "근속가봉은 넣지 않았어요"를 밝히는 데 쓴다(아래 "생애 봉급의 계산 가정").
- `tracks` 는 계급 사다리(`ladders`)와 직종별 규정(`items`)이다.
- `leave.compensation`(연가보상비, #33): `rate`·`divisor`·`maxDays`(20일) 말고 `roundTo`(끝수 처리 단위 10원 — 국고금 관리법
  제47조제1항), `midYear`(6월 30일 기준: `month`·`day`·`minRemainingDays` 10·`days` 5·`optional` — 기관이 6월 30일 기준을 하지
  않을 수 있다), `retire.beforeJulyMaxDays`(6월 30일 이전 퇴직 10일 이내)를 둔다(수당규정 제18조의5제2항~제4항, 업무지침 제7장
  Ⅶ. 3.). 금액은 `calc/leave-bank.ts compensationAmount` 하나로 낸다: **일수까지 곱한 뒤** 원 미만, 다시 `roundTo` 원 미만을 버린다.
  1일 단가를 먼저 버리고 곱하면 업무지침 예시(449,100원)와 어긋나므로 화면에 '1일 단가'를 두지 않는다(PLAN 부록 O).
- `leave.saving`(연가 저축, #33): `availableFrom`(`'nextYear'`)·`overtimeAvailableFrom`(`'nextMonth'`)·`order`(`'oldest-first'`)·
  `autoCarryUnderDay`·`expires`(`'never'` = 소멸시효 없음)·`compensated`(false)·`recommended`(`minDays` 10, `noticeBy` `'03-31'`).
  **`null` 인 칸은 그 직종의 원문으로 확인하지 못한 칸**이다(지방 일반직은 국가 예규에서 온 칸 — 쓰는 시기·순서·소멸·권장 연가 —
  을 `null` 로 둔다. 국가 값으로 대신하지 않는다). `uncompensatedBonus`(`{ source }` 또는 `null`)는 '연가보상비를 받지 못한 날이
  남으면 다음 해 1일 가산'(복무규정 제15조제3항제2호)을 예규 (2)(나)·(다)의 판정으로 **힌트만** 보일 근거다(지방 일반직은 `null` — 준비 중).
  저축연가 통장·연말 정리(`calc/leave-bank.ts` 의 `savingsLedger`·`savingsAvailableOn`·`yearEndSplit`·`overCapUnsavedDays`·
  `bonusLeaveHint`)가 이 값으로 셈한다: `availableFrom`·`order` 가 `null` 이면 날짜로 막지 않고 넣은 것 − 쓴 것의 합계만,
  `autoCarryUnderDay` 가 `null` 이면 끝자리 자동 저축을 셈하지 않는다.

## 언제 무엇을 확인하나

| 시기 | 확인할 것 | 참고 |
|---|---|---|
| 1월 | **봉급표**(공무원보수규정 별표 3·4·8·10·11), 수당 규정 | 2026년 봉급표는 2026. 1. 2. 개정됐다 |
| 6~7월 | **다음 해 공휴일**(월력요항, 천문연 달력자료) | 천문연 달력자료의 2027년분은 2026. 6. 30.에 만들어졌다 |
| 수시 | 임시공휴일 지정, 복무규정·임용령·수당규정 개정 | 지정·개정되면 그때 |

잊지 않도록 **"규정 데이터 점검" 워크플로**가 매달 한 번 돌면서 손봐야 할 것이 있으면 이슈를 만든다.
직접 확인하려면:

```bash
npm run rules:check                       # 오늘 기준
npm run rules:check -- --date 2027-01-04  # 그날 기준으로 미리 보기
```

## 하는 방법

### 새 봉급표가 나왔을 때 (예: 2027년)

별표 3 과 함께 **별표 4·8·10·11 도 같은 날 개정된다**(2026년은 모두 2026. 1. 2.). 다섯 표를 모두 확인할 때까지는
확인한 표만 넣는다. `payTables.items` 는 표 단위로 넣을 수 있고(`table10` 하나만 넣어도 된다), 넣지 못한 표가
남아 있으면 `pending` 에 `payTables` 를 남긴다. 그동안 그 표는 이전 해 값으로 계산하고 화면에 "○○년 표
기준(확정 전)"이 뜬다. 별표 4·8·10 은 별표 3 과 같은 방법(`pdftotext -layout`)으로 뽑고, 별표 11 은 두 단(1~20,
21~40호봉)이라 줄마다 (호봉, 값, 호봉, 값)으로 읽는다(테스트가 그렇게 대조한다).
별표 11 을 새 해 파일에 넣을 때는 **`longServiceAddOn` 도 함께 넣는다**(표 단위로 합치므로 빠뜨리면 이전 해 값이
이어지지 않는다 — 테스트가 막는다). 금액은 제30조의2제2항을 다시 확인해 발췌본
(`pay-reg-articles-separation.txt` 와 같은 형식)과 함께 넣는다. 제30조의2제2항은 2011년부터 2026년까지 해마다
1월에 개정되었다(발췌본에 적힌 그 항의 개정 이력).


1. 국가법령정보센터에서 공무원보수규정을 열어 **시행일과 공포번호**를 확인한다.
2. 별표 3을 PDF로 내려받아 글자로 뽑는다.

   ```bash
   pdftotext -layout 별표3.pdf docs/sources/2027/pay-reg-table3-salary.txt
   ```

   파일 맨 위에 출처·조회일을 `#` 주석으로 적는다(2026년 파일 참고).
3. `data/2027.json` 에 `salary` 항목을 넣는다. 형식은 2026년과 같고 `source.revised` 는 별표의 개정일이다.
4. `pending` 에서 `"salary"` 를 지우고, 다른 항목도 모두 다시 확인했다면 `status` 를 `"verified"` 로 바꾼다.
   `laws.pay` 를 새 판본으로, `verifiedAt` 을 오늘로 고친다.
5. `npm test` — 봉급표가 발췌본과 **한 칸도 다르지 않은지**, 호봉·직급 순으로 늘어나는지 검사한다.
   발췌본이 없으면 테스트가 실패한다.

### 다음 해 파일을 처음 만들 때

```json

  "schema": 1,
  "year": 2028,
  "extends": 2027,
  "target": { "id": "national", "label": "국가공무원" },
  "status": "partial",
  "verifiedAt": "2027-07-01",
  "pending": ["salary", "payTables"],
  "laws": {},
  "holidays": { "items": [], "source": { "law": "holidayRegulation", "article": "제2조·제3조" } }

```

`data/` 에 `<연도>.json` 을 두기만 하면 코드 수정 없이 반영된다.

### 공휴일을 넣을 때

- 관공서의 공휴일에 관한 규정 제2조(공휴일)·제3조(대체공휴일)와 그 해 달력자료(음력 명절 날짜)를 함께 본다.
- 일요일은 넣지 않는다. 대체공휴일은 날짜와 이름을 따로 한 줄로 넣는다.
- `npm test` 가 대체공휴일 규칙과 목록이 맞는지 다시 계산해 본다.
- **임시공휴일**은 지정되면 한 줄 추가하고 `source.note` 에 지정 근거를 적는다.

### 그 밖의 항목이 바뀌었을 때

값을 고치고 `source`(조항·개정일), `laws`(판본), 발췌본, `verifiedAt` 을 함께 고친다.
`tests/unit/rules-data.test.ts` 의 "법령 원문 발췌본과 대조"에 해당 값의 대조가 있으면 그것도 맞춘다.

## 직종을 더하거나 고칠 때

직종은 코드의 닫힌 목록(`TRACK_IDS`: `general` `localGeneral` `police` `coastGuard` `fire` `teacher` `foreign`
`militaryCivil` `otherSpecial`)이다. 저장 형식이 이 목록을 검사하므로 **새 직종을 더하면 저장 형식 버전을
올린다**(지방 일반직 `localGeneral` 은 v7 에서 더했다). 이미 있는 직종의 규정을 채우는 것은 데이터만 고치면 된다.

**해석 규칙**(`src/lib/rules/career.ts` 의 `resolveCareer` 한 곳). 항목(`FeatureKey`: `stepRaise`
`promotionStep` `retirement` `probation` `minService` `longService` `seniorTreatment` `leaveAnnual`
`leaveAdvance` `leaveCompensation` `leaveLongService` `leaveSaving` `diligence` `holidayBonus` `seniorAllowance`
`positionAllowance`)마다

1. 직종(일반직은 `byPayTable[봉급표]` 가 먼저)에 **덮어쓰기 값**이 있으면 그것을 쓴다. 값이
   `{ "status": …, "reason": … }` 이면 그 항목은 꺼진다(숫자 없이 상태와 사유를 보인다).
2. 없고 `applies[항목]` 에 **적용 근거**가 있으면 기본 구역(일반직 값)을 쓴다. 근거 법령 화면에는
   적용 조항과 함께 숫자가 나온 기본 구역의 조문·`note`(해석·미반영 단서)를 '적용하는 조문'으로 같이 보인다.
3. 둘 다 없으면 — 일반직은 기본 구역, **그 밖의 직종은 자동으로 `pending`(준비 중)**이다.

**일반직이 아닌 직종은 근거 없이 기본 값을 쓰지 않는다.** 데이터를 빠뜨리면 틀린 숫자 대신 '준비 중'이 뜬다.
`status: "ready"` 직종(경찰·소방·교원)은 테스트가 모든 항목을 덮어쓰기나 `applies` 로 명시했는지 본다.

`status` 세 값(꺼진 항목, 데이터에 쓰는 값):

| 값 | 뜻 | 화면 |
|---|---|---|
| `pending` | 원문을 아직 확인하지 못했다 | 준비 중 |
| `none` | 그 직종에는 없다(교원의 근속승진·연가보상비 등) | 해당 없음 |
| `external` | 조례·기관 기준 등 다른 규정이 정해 여기서 계산하지 않는다(소방 장기재직휴가, 교사 직급보조비) | 다른 기준 |

코드에는 네 번째 값 `input`(화면 '입력 필요')이 있다. 데이터에는 쓰지 않고, 사다리가 있는 직종에서 계급을
고르지 않았거나 목록에 없는 계급이 저장돼 봉급·정년을 셀 수 없을 때 계산이 만든다(원문 미확인이 아니므로
'준비 중'과 구별한다).

`status` 는 원문이 말하는 대로 고른다. **'표에 없다'는 `none` 이 아니다** — 비고가 다른 기준을 정하면
`external`, 모르면 `pending`. 월급날 기본값처럼 해석이 들어간 기본값은 `note` 에서 단정하지 않는다
('기본으로 뒀어요. 실제 월급날로 맞춰 주세요').

- **계급 키**는 사다리의 키다(일반직·우정 `'9'`~`'1'`, 경찰 `'순경'`…, 외무 `'1'`~`'6'`, 교원 `'교원'` 하나).
  `monthsByGrade`·`yearsByRank`·`amountByGrade` 의 키도 이 키다. 일반직의 `'1'`~`'9'` 는 저장 형식이 코드
  상수로 검사하므로 바꾸지 않는다.
- **봉급표 열 키**: 사다리 계급의 `payColumn` 은 그 봉급표(`salary.table` 또는 `payTables.items.<id>.table`)의
  열 키다. `null` 이면 봉급표에 열이 없는 계급이다(`selectable: false` 로 고를 수 없게 한다).
- 직종의 칸 중 화면이 직종 id 대신 보는 표시(#31):
  - `seriesScope`(`'national'`·`'local'`): 직렬 고르기를 보일지와 어느 직렬 표인지. 일반직 `national`, 지방 일반직 `local`,
    그 밖은 없음(직렬을 묻지 않는다). 화면은 직종 id 로 가르지 않고 이 값을 본다.
  - `payday.options`: 그 직종의 월급날 선택지. 없으면 기본 구역(별표 30)의 네 행. `payday.source` 는 기본 구역과 다른 근거일 때만
    (지방공무원 보수규정 제19조). 해석 결과 `CareerRules.payday.options` 가 이 값을 돌려준다.
  - `leaveUnits`: 연가 단위를 기본 구역과 다른 근거로 정할 때. `halfDayHours: null` 은 반일 단위를 원문으로 확인하지 못했다는 뜻
    (새 반일 기록을 받지 않는다 — `calc/leave.ts checkNewLeave`). 기본 구역(`leave.units`)의 반일은 늘 숫자다.
  - `leaveAnnual.tenureBasis`: `'day-before-use'`(사용 직전일, 국가 예규) 또는 `'year-start'`(그해 처음 연가가 생기는 날의
    재직기간으로 센 일수만 쓰고, 그 뒤 구간이 바뀌는 날은 숫자 없이 '준비 중' — `pendingGrantChange`). 기준일을 원문으로
    확인하지 못한 직종에 `'year-start'` 를 쓴다(일반직 값으로 대신하지 않는다, PLAN 부록 E-Q4). 일정('연가 N일')은 연초 재직기간으로
    센 일수가 그 구간이 되는 첫 1월 1일에 두고 '늘어나요'라고 하지 않는다(PLAN K16).
  - `longService.rosterName`: 근속승진 일정 문구의 명부 이름(원문 글자 그대로 — 국가 '승진후보자명부', 지방 '승진후보자 명부').
    없으면 '명부'.
  - `leaveFirstYear`: 연도 중 임용·퇴직한 해의 연가 계산(개월 환산·반올림)을 기본 구역(국가 복무규정 제17조제2항)과 다른 근거로
    정할 때(지방: 지방공무원 복무규정 제7조의2제2항·제3항제2호). 숫자는 국가와 같고 '같은 값 감시'가 견준다. 연가 화면의 본문
    근거(연가 일수·임용 연도·연가보상비)는 손으로 쓰지 않고 해석 결과의 `source` 에서 읽는다.
  - `payCalc`(`prorate`·`leaving`): 생애 봉급 문구의 봉급 계산 근거(달 가운데 임용·승급한 달의 일할계산, 5년 이상 근속한 공무원이
    달 가운데 면직한 달의 봉급)를 기본 구역 `salary.calc`(공무원보수규정 제22조①·제24조①1호)와 다른 근거로 둘 때(지방: 지방공무원
    보수규정 제21조①·제23조①1호). 숫자는 없다. 해석 결과 `CareerRules.payCalc`. 생애 봉급의 근거 줄은 이것과 `stepRaise.source`·
    `CareerRules.payday.source`(직종 근거, 없으면 기본 구역)·`diligence.source` 로 만든다(`src/lib/app/cite.ts`).
  - `workHoursSource`·`mealSource`: 값은 기본 구역(근무시간·정액급식비)을 그대로 쓰되 근거 조문이 다른 직종(지방: 복무규정 제2조,
    수당규정 제18조). 근거 법령 화면이 공통 칸 대신 직종 칸에 보인다.
  - `leaveCompensation.payCondition`(기본 구역 `leave.compensation.payCondition` 도): 연가 화면 문장 '보상 일수와 지급 여부는
    ○○에 따라 달라요'의 ○○(국가 '권장연가 등 기관 방침', 지방 '소속 지방자치단체의 조례와 예산, 기관 방침'). '같은 값 감시'는
    이 글자를 빼고 견준다.
  - `compRoundingNote`(`text`·`source`, #33): 연가보상비를 지방자치단체가 지급할 수 있는 직종(시·도 소속 소방, 지방 일반직)의
    끝수 각주. 지방회계법 제55조는 10원 미만 버림을 '할 수 있다'로 두어 기관마다 다를 수 있다. 연가보상비 어림 창은 이 칸이
    있을 때만 각주를 그린다(직종 id 로 가르지 않는다). 국가가 지급하는 직종(일반직·경찰·해양경찰)에는 두지 않는다.
  - 연가 저축(`leaveSaving`): 경찰·해양경찰·소방은 `applies`(국가공무원 복무규정 적용·준용), 교원은 `none`(교원휴가 예규 제10조),
    지방 일반직은 지방 원문(지방공무원 복무규정 제7조의10·제7조제4항)으로 덮어쓴다. `leaveScreen.savingCarryOver` 는 이 항목과
    어긋나지 않아야 한다(false ⇔ `none` — 테스트). 연가 화면의 부여 일수 도움말은 `savingCarryOver` 가 아니라 이 항목의 상태를 본다.
  - `payday.options[].orgs` 끝의 괄호 속(지방 17일의 '교육청·학교')은 월급날 단추 글자('교육청·학교 17일')와 대화의 도움말에 쓴다.
  - `payTables` 의 길이: 둘 이상이면 봉급표를 고르는 직종(일반직)이다. 봉급표 칸·봉급표 검사·꼬리말의 '(별표 4)'는 직종 id 가
    아니라 이 길이로 정한다(저장 형식의 `GENERAL_PAY_TABLES` 검사만 코드 상수).
- 화면 글: `label`(직종 이름)·`scope`(직종 칩 아래 한 줄)·`pendingReason`(자동 준비 중의 사유)·
  `workHoursNote`·`leaveNote`·`leaveScreen`(연가 화면의 기록 시스템·저축 이월 여부)·`notes`.
  직종 이름 뒤 조사는 코드가 받침을 보고 붙이므로(`josa()`) 이름만 적는다.
- 캐릭터 형태는 `data/character.json` 의 `evolution`(사다리별 `byRank`, 사다리가 없으면 `byTenure`)이다.
  사다리를 더하면 모든 계급을 형태에 매핑해야 한다(테스트).

## 직렬 목록과 호봉이 꾸미기 (법령 값이 아님)

`data/series.json`(`schema: 3`)은 직군·직렬·직류 이름을 원문 그대로 담고, 직렬마다 호봉이가 드는 소품 테마(`theme`)를
붙였다. 계산에는 쓰지 않는다. schema 3(#38)은 찾기 사전 `finder` 를 더했다(아래 '넓게 찾기').

- 직군마다 `scope` 와 `source` 가 있다. `scope: "national"` 은 공무원임용령 별표 1(일반직 직급표)·별표 2(우정직군)의
  직렬 52개, `scope: "local"` 은 지방공무원 임용령 별표 1 의 직렬 46개(원문 순서: 행정·과학기술·관리운영 직군)다.
  어느 표를 쓰는지는 직종 데이터의 `seriesScope`(일반직 `national`, 지방 일반직 `local`)가 정한다. 화면은 직종 id 를 보지 않는다.
- 직렬마다 `jikryu`(직류, 원문 표 순서)를 적는다. 직렬과 같은 이름의 단일 직류도 표 그대로 적고, 찾기에서는 직렬로 묶는다.
  국가 '교육행정'은 행정 직렬의 직류이고, 지방 '교육행정'은 행정 직군의 직렬이다(#31).
- 이름 색인은 (scope, 이름) 키다(`src/lib/character/series.ts` 의 `seriesByKey`·`searchSeries`·`groupsOf`). 국가·지방에 같은 이름의
  직렬이 38개 있어 이름 하나로 키를 삼으면 덮인다. 같은 이름은 두 표에서 같은 테마를 쓴다.
- 찾기는 공백을 지운 글자가 직렬·직류·직군 이름에 들어 있으면 맞고, 지금 표 → 맞음의 세기(직렬 이름 같음 < 직류 이름 같음 <
  앞부분 < 안 < 직군 이름) → 원문 순서로 늘어놓는다(`searchSeries`, R0). 다른 표에만 있는 이름은 고를 수 없고 안내 상자로만
  보인다(직종을 저절로 바꾸지 않는다). 이 위에 넓게 찾기(#38)를 얹었다(아래).
- 직류로 고르면 저장본에 `profile.series`(직렬)와 `profile.seriesJikryu`(직류, v7)를 함께 담는다. 직렬만 고르면 직류는 `null`.
  직류는 카드·결산 카드·공유 문구·소품 계산에 쓰지 않는다.
- 원문 발췌본은 국가 `docs/sources/2026/appointment-decree-table1-grades.txt`·`table2-postal.txt`, 지방
  `local-appointment-decree-table1-grades.txt`. 직렬·직류 이름이 발췌본에 있는지는 테스트(`tests/unit/character-custom.test.ts`,
  `tests/unit/rules-data.test.ts` 의 '지방 발췌본과 대조')가 본다. 표의 칸 줄바꿈으로 끊긴 이름(국가 `전자통신기술`, 지방
  `열관리운영`·`회계처리운영`)만 그림으로 대조하고 테스트의 예외 목록에 적었다.
- 지방 직렬표 밖에 조례로 만든 직류(지방공무원 임용령 제3조제1항 단서, TODO T24)는 찾기에 없을 수 있다. 직렬로 고르면 된다.
- 직렬이 새로 생기면 그 직군에 항목을 더하고 테마를 고른다(테마는 `character.json` 의 `custom.props` 중
  `kind: "series"`). 이름이 바뀌면 새 이름으로 고치고 **옛 이름을 `aliases` 에 남긴다** — 저장본
  (`profile.series`)은 직렬 이름을 그대로 담으므로, 옛 이름이 사라지면 그 사용자의 소품이 기본(결재판)으로 돌아간다.
- 직렬이 없어져도 저장본은 거부하지 않는다(형식만 본다). 화면에 이름이 안 보이고 소품이 기본으로 돌아갈 뿐이다.
  다만 두 표 어디에도 없는 이름은 아래 '직접 적은 이름'으로 보인다(옛 이름은 `aliases` 에 남겨야 지금 이름으로 보인다).

### 넓게 찾기와 찾기 사전(#38)

사용자 요청: "경찰행정 직렬도 없다." 법령 표의 이름과 사람들이 부르는 이름이 다를 때 막히지 않게 한다. 코드는
`src/lib/character/series.ts` 의 `findSeries`, 화면은 `src/screens/profile/SeriesPicker.svelte`(첫 입력의 대화·한 번에 쓰기·설정이 함께 쓴다).

- **찾는 차례.** R0 원문 이름으로 찾기(`searchSeries` 그대로 — 표에 실제로 있는 이름이 늘 먼저다).
  두 표 어디에서도 하나도 못 찾았을 때만 R1 꾸밈말 떼기(앞의 `국가직`·`지방직`·`국가`·`지방`·`N급`, 뒤의 `공무원`·`직렬`·`직류`·
  `직군`·`직`·`N급` — 남는 글자가 2자 이상일 때만 뗀다. '세무직' → 세무, '9급 사회복지직 공무원' → 사회복지, '교정직 9급' → 교정).
  꾸밈말 떼기는 표의 이름을 깎지 않는다: 한 번 뗄 때마다 지금 글자가 두 표의 이름(직군·직렬·직류·옛 이름)이면 거기서 멈추고,
  앞을 뗄지 뒤를 뗄지·`지방직`을 뗄지 `지방`만 뗄지를 모두 해 보아 가장 적게 떼어 표의 이름에 닿는 것을 쓴다('인사조직 공무원' →
  인사조직, 지방 표의 '지방세직' → 지방세, '지방 직업상담' → 직업상담). 어느 길로도 표의 이름에 닿지 않으면 가장 많이 뗀 글자를 쓴다.
  두 표의 158개 이름 × 꾸밈말 10가지를 테스트가 모두 돈다(`stripModifiers`) → R1' 줄임말 풀기
  (`finder.short`, '교행' → 교육행정) → R2 조각 찾기(꾸밈말을 뗀 글자 **안에 든** 지금 표의 직렬·직류 이름, 2자 이상·찾는 글자보다
  짧은 것. 한 직렬은 가장 긴 조각으로 한 번, 긴 이름 → 원문 순서로 6개까지. '경찰행정' → 행정).
- R2 는 R1 까지 **두 표 어디에서도** 못 찾았을 때만 한다(다른 표에 있으면 다른 표 안내가 답이다 — '보건진료직'을 국가 표에서
  찾으면 '보건' 조각이 아니라 지방 표의 보건진료를 알린다). 조각으로 찾은 것은 **짐작**이라 상태 줄에 '이름에 든 글자로 찾았다'고
  밝히고(하나면 그 이름까지) Enter 로 저절로 고르지 않는다. 같은 길이의 조각이면 직렬 이름을 직류보다 앞에 둔다('운전').
- 화면은 한글을 조합하는 동안('경ㅊ')과 끝 글자가 자모일 때는 찾지 않고, 잠깐(0.35초) 쉬었을 때 찾는다(상태 줄이 친 글자를 되풀이해
  읽지 않게). Enter 와 칸을 떠날 때는 바로 찾는다.
- 결과에는 어떻게 찾았는지(`how`: `as-is`·`strip`·`short`·`piece`·`none`)와 실제로 쓴 글자(`used`)가 담기고, 상태 줄은 이것으로 쓴다.
- **찾기 사전 `finder`** 는 법령의 이름이 아닌 말을 원문 이름으로 **이어 주기만** 한다. 여기에 든 말은 저장 키가 아니다(고르면
  저장본에는 원문 이름이 담긴다). 테스트(`tests/unit/series-find.test.ts`)가 지키는 규칙: `say` 는 두 표 어디에도 없는 이름(있으면
  표가 답이다), `short[].means` 는 어느 표엔가 있는 직렬·직류 이름, 모든 글자는 `SERIES_KEY_RE` 형식, 설명은 해요체.
  - `short`(줄임말): 공무원 사이에서 굳은 줄임말 **셋만** — `교행`(교육행정)·`일행`(일반행정)·`사복`(사회복지). 화면에 '줄임말'이라고
    밝힌다. 더 넣으려면 그 근거를 이 절에 적는다.
  - `common`(흔히 부르는 이름): 근거가 있는 것만. 지금은 `경찰행정` 하나. 근거: 경찰청·경찰서에서 일하는 일반직(행정직) 공무원을
    흔히 이렇게 부른다 — 서울신문 2020-04-15 「[SOS초시생-⑨경찰행정] "경찰서에도 일반직 있어요…"」(인사혁신처 협조 인터뷰,
    https://m.go.seoul.co.kr/news/2020/04/15/20200415025002). 법령이 아니라 '흔히 부르는 말'의 근거로만 쓴다. `경찰행정` 은 국가·지방
    직렬표 어디에도 없는 이름이고('경찰'이 든 직렬은 국가 표의 `철도경찰` 뿐), 경찰청 소속 일반직은 공안업무 봉급표(별표 4) 대상에
    적혀 있지 않아(`docs/sources/2026/pay-reg-table1-classification.txt`) 봉급표 안내는 따로 하지 않는다. 꾸밈말을 뗀 찾는 글자가
    `say` 와 같을 때 설명을 안내 상자에 보이고, 조각 찾기와 직종 말은 그대로 함께 돈다.
- **직종 말.** 찾는 글자(공백을 지운 것)에 다른 직종의 이름(규정 데이터 `tracks.items[*].label`, 공백을 지운 2자 이상)이 들어 있으면
  그 직종이 따로 있다고 알린다(`trackWordNote`, `src/lib/app/track.ts`). 지금 직종과 직렬 표가 있는 직종(`seriesScope`)은 빼고,
  겹치면 긴 이름만('해양경찰행정' → 해양경찰). 지금 표에서 이름이 같게 찾았으면 보이지 않는다. 직종을 저절로 바꾸지 않고
  [직종 고르기로 가기]만 둔다. label 뒤에 '공무원'을 기계적으로 붙이지 않는다('교원 공무원'이 되지 않게). 직종 말이 보이면 상태 줄 끝에도
  짧게 알리고, Enter 로 저절로 고르지 않는다('경찰' → 철도경찰 하나가 나와도 경찰공무원이면 직종이 답이다).
- **옛 이름.** 표의 이름이 바뀌거나 다른 직렬과 합쳐진 직렬은 지금 직렬 항목의 `aliases` 에 예전 직렬 이름을 둔다(예전 저장본도 맞는다).
  옛 이름으로 찾으면 목록과 다른 표 안내에 `형사법무 (예전 검찰 직렬)` 처럼 함께 보인다(`SeriesHit.alias`). '옛 이름'이라고 쓰지 않는다:
  형사법무는 두 직렬을 합친 것이라 형사법무가 예전에 '검찰'이라는 이름이었던 것처럼 읽히면 원문을 넘는다. 옛 이름은 **같을 때와 2자 이상의
  앞부분일 때만** 맞는다(안에 든 글자로 맞추면 '사무'·'공안'·'수사'에 지금은 없는 이름이 끼어든다). 앞부분으로만 맞은 것('마약')은 Enter 로
  저절로 고르지 않고, 같은 세기면 지금 이름으로 맞은 것 뒤에 둔다. 공무원임용령 개정문·부칙 원문으로 확인한 **직렬 단위의 이름 변경·통합만**
  넣었다(발췌본과 대조 테스트 `tests/unit/series-find.test.ts`):
  - `형사법무` ← `검찰`·`마약수사`(통합): 대통령령 제36728호(2026. 10. 2. 시행) 제22조 "검찰 직렬란 및 마약수사 직렬란을 각각 삭제"와
    부칙 제4조 "검찰직렬과 마약수사직렬의 5급 이하 공무원은 … 형사법무직렬의 해당 직급으로 임용된 것으로 본다"
    (`docs/sources/2026/appointment-decree-rename-36728-hyeongsabeommu.txt`).
  - `형사법무` ← `검찰사무`(이름 변경 뒤 통합): 대통령령 제24124호(2012. 9. 28.) "별표 1 행정직군의 검찰사무직렬란을 다음과 같이 한다"(새 칸 그림 판독 `검찰`)
    — 검찰사무 → 검찰 → 형사법무. 이 개정에는 경과조치가 없어 개정문과 그림만이 근거다(`…-rename-24124-geomchal.txt`).
  - `철도경찰` ← `철도공안`(명칭변경): 대통령령 제25000호(2013. 12. 16.) 부칙 제7조(`…-rename-25000-cheoldogyeongchal.txt`).
  - 넣지 않은 것(TODO T50): 직류 단위의 옛 이름(운수 → 일반행정, 경비 → 방호, 야금 → 금속, 약제 → 약무, 정보관리 → 데이터,
    표지운영·등대관리 → 해양교통시설, 교회·분류 → 교정, 지방 계리운영 → 회계처리운영 등 — 원문으로 확인했지만 `aliases` 는 직렬의
    옛 이름이라 직류에 붙일 칸이 없다), 두 곳을 가리키는 `통신`(일반직 통신 → 방송통신, 기능직 통신 → 통신운영), 국가 2008년 이전
    `교육행정` 직렬(지금 국가 표의 직류 이름이자 지방 표의 직렬 이름이라 옛 이름으로 두면 #31 의 다른 표 안내가 깨진다),

### 직접 적은 이름(#38)

법원·국회·선관위·헌법재판소처럼 두 표 밖의 직렬을 가진 사람이나, 자기가 부르는 이름을 쓰고 싶은 사람을 위한 마지막 길이다.
**저장 형식은 바꾸지 않는다**(v7 그대로, 새 칸·새 표시 없음).

- 뜻: `profile.series` 가 **국가·지방 두 표 어디에도 없는**(직군·직렬·직류·옛 이름 모두) 이름이고, `SERIES_KEY_RE` 형식에 맞고
  12자 이하이면 '직접 적은 이름'이다(`isOwnSeriesName`). 다른 표에만 있는 이름(일반직에서 지방 `교육행정`)은 지금처럼 숨기고 짝을 권한다.
- 찾는 칸의 글자(앞뒤 공백을 떼고 겹친 공백을 하나로)가 2자 이상이고 형식에 맞고 12자 이하이고 두 표에 없으면 목록 아래에
  [‘{이름}’ 그대로 쓰기]를 보인다(개인정보 안내가 단추 앞에 있고 단추의 설명으로 이어진다). 형식에 맞지 않으면 단추 대신 까닭 한 줄.
  두 표 어디에서든 이름이 같게 찾았으면 보이지 않는다. 직종 말이 알린 직종 이름을 꾸밈말을 뗀 글자에서 빼고 2자도 남지 않으면
  ('경찰'·'경찰청'·'9급 소방 공무원') 직종이 답이라 보이지 않는다('경찰행정'은 '행정'이 남아 보인다).
- 보이는 곳: `seriesNameOf` 가 그 글자를 돌려주므로 홈 상태창·설정·카드(사용자가 켰을 때만)에 나온다. **'직렬'을 붙이지 않는다**
  (홈·카드 `경찰행정` — 표의 이름은 지금처럼 `행정 직렬`, `seriesWord`). 직류는 없다. 소품 테마가 없어 'auto' 는 직렬을 고르지 않았을
  때와 같다. 설정·목록에는 `경찰행정 (직접 적은 이름)` 으로 보인다.
- 직접 적은 이름도 이 브라우저에만 저장한다(내려받은 임용정보 패키지에는 들어간다 — 지금 직렬과 같다). 고치지 않고 그대로
  보이므로 이름·기관처럼 사람을 알아볼 수 있는 말은 넣지 말라고 안내한다.
- 이 뜻 때문에 예전에 '목록에 없는 저장값'으로 숨던 두 표 밖의 이름(데이터에서 사라진 옛 직렬 이름 포함)도 이제 그대로 보인다.
  이름이 바뀐 직렬은 반드시 `aliases` 에 옛 이름을 남긴다.

`data/character.json` 의 `custom` 구역은 호봉이 꾸미기(몸 색 `bodies`·볏 `crests`·깃 `plumes`·장식 `decos`·
손 소품 `props`)와 슬롯 숨김(`hide`)이다. 저장본(`character.look`)은 이 id 만 담고, **목록에 없는 id 는
거부하지 않고 보존**한다(같은 저장 형식 버전에서 목록이 늘어도 예전 사본이 백업 전체를 거부하지 않게). 그릴 때만
기본값으로 대신한다. id 를 지우거나 이름을 바꾸면 그 id 를 고른 사용자는 기본 모습으로 돌아가므로, 되도록 id 는
그대로 두고 그림·색만 고친다. 색 치환이 어느 칸에 적용되는지는 `src/lib/character/regions.ts` 머리말에 있다.

**형식은 앞으로도 지킨다(같은 v5 안의 약속).** 위 보존 규칙은 새 값이 지금 형식에 맞을 때만 예전 사본에서 지켜진다.
그래서 목록을 늘릴 때는 다음을 지킨다(`tests/unit/assets.test.ts` 가 지금 목록을 본다).

- 새 직렬 이름·옛 이름(`aliases`)은 `SERIES_KEY_RE`(한글·영숫자·가운뎃점 `·`, 낱말 사이 띄어쓰기 한 칸, 20자까지)를 지킨다.
  가운뎃점·띄어쓰기는 아직 원문에 없지만 v5 에서 미리 받는다.
- 새 칸(예: `deco.hat`)을 더하거나 열거값(`pointer`)·숫자 범위(음량 0~100 정수)를 넓히면 예전 사본이 버리거나 거부하므로
  **저장 형식 버전을 올린다**(부록 C: 더 새 버전 저장본은 예전 사본이 건드리지 않는다).
- 특정직의 손 소품 `'auto'` 는 호봉 소품(9호봉부터 결재판)이다. 직종 소품(손전등 등)은 직접 고를 때만 든다 —
  직종은 꼭 고르는 계산 값이라 기본 모습·카드가 직종을 드러내지 않게(부록 F). 모르는 소품 id 도 호봉 소품으로 그린다.

## 생애 봉급의 계산 가정 (#30)

홈의 '생애 봉급' 창은 규정 값을 새로 넣지 않고 이미 있는 봉급표·정기승급·정년·보수 지급일·정근수당 규정으로 셈한다
(`src/lib/calc/salary.ts` 의 `lifetimeSalary`, `src/lib/calc/lifetime.ts`). 문구는 `src/lib/app/lifetime-copy.ts` 한 곳에 있다.

**계산이 따르는 가정**

| 무엇 | 가정 | 근거 |
|---|---|---|
| 봉급표 | 오늘이 속한 해에 적용하는 봉급표 한 장(그 해 파일이 없으면 가장 가까운 이전 연도)을 임용일부터 끝나는 날까지 쓴다 | 지갑 창의 '지금까지 번 봉급'(`cumulativeSalary`)과 같은 방식 |
| 계급·호봉 | 지금 계급 그대로, 정기승급만(승급기간마다 한 호봉, 최고호봉에서 멈춤). 승진·강임·승급 제한·휴직은 넣지 않는다 | 공무원보수규정 제13조(`pay-reg-articles.txt`) |
| 달 가운데 임용·승급 | 그 달 날수로 나눈다 | 제22조제1항, 제4조제6호(`pay-reg-articles-separation.txt`). 지방 일반직은 지방공무원 보수규정 제21조제1항(`local-pay-reg-articles.txt`) — 화면 글은 `salary.calc`·직종 `payCalc` 에서 만든다 |
| 끝나는 날 | 기본은 정년퇴직일(연령·계급정년 중 이른 날). 사용자가 **퇴직 예정 달(연·월)** 을 정하면 그 달 말일(저장 형식 v6 의 `plan.retireMonth`, 이번 달 ~ 연령정년 퇴직일의 달). 늘 달의 말일이고 **그날까지(포함)** 봉급을 센다 | 국가공무원법 제74조제4항 등(직종별 `retirement`). 테스트가 모든 직종의 퇴직일이 말일인지 본다 |
| 날짜가 아니라 달 | 퇴직일을 날짜로 받지 않는다. 달 가운데 그만둔 달의 봉급은 근속 연수·그 달 근무 일수·퇴직 사유에 따라 전액이거나 날짜만큼이라 날짜로는 틀린 숫자가 나올 수 있다. '그 달 말일까지 다닌다'는 가정은 어느 해석에서도 그 달 전액이다 | 제22조제1항, 제24조제1항제1호(`pay-reg-articles-separation.txt`). 지방 일반직은 지방공무원 보수규정 제21조제1항·제23조제1항제1호 |
| 금액의 범위 | 봉급만. 수당·세금·기여금·퇴직급여는 넣지 않는다 | — |
| 합이 맞게 | '앞으로 벌 봉급'은 따로 더하지 않고 `총액 − 지금까지`로 정의한다(원 단위 합이 늘 맞는다). 화면은 만 원 미만을 버리므로 '앞으로'만 `보이는 총액 − 보이는 지금까지`(만 원 단위)로 보인다 | `shownRemaining` |
| 월급날 횟수 | `임용일 ≤ 월급날 ≤ 오늘`은 받은 쪽(오늘 포함), `오늘 < 월급날 ≤ 끝나는 날`은 남은 쪽. 달은 끝나는 달까지만 훑는다. 주말·공휴일이면 당겨진 날로 센다 — 1~3일 지급처럼 다음 달 월급날이 이번 달로 당겨져 그날이 지났으면 받은 쪽에 들어가, 당겨지지 않았을 때보다 '남은' 횟수가 하나 적다 | 제20조제2항(토요일·공휴일이면 그 전날) |
| 정근수당 횟수 | 지급 달(1·7월) 1일에 재직 중이고, 그 앞 지급대상기간(6개월) 가운데 1개월 이상 봉급을 받았고(임용일부터 기준일까지 1개월 이상), 지급일이 아직 오지 않은 것. 금액은 세지 않는다 | 공무원수당 등에 관한 규정 제7조제1항(`allowance-reg-articles.txt`). `diligenceBonus` 와 같은 판정 |
| 해가 바뀌는 횟수 | 오늘 뒤~끝나는 날 사이의 1월 1일 수. **봉급표가 바뀌는 횟수가 아니다** | 달력 |

금액(번 날 기준, 오늘까지 일할)과 횟수(월급날이 지났는지)는 기준이 달라, 이번 달 월급날이 지난 마지막 달에는
'앞으로 벌 봉급'이 남았는데 남은 월급날은 0번일 수 있다. 화면이 그 줄에서 "이번 달 월급날은 지났어요"라고 말한다.

**넣지 않은 것과 까닭**

- 명절휴가비 횟수: 설날·추석 날짜는 그 해 공휴일 데이터에서만 온다(데이터가 없는 해가 대부분이다).
- 남은 근무일 수: 공휴일 데이터가 없는 해는 주말만 쉬는 날로 세게 된다.
- 수당을 더한 합계: 일부 수당만 더하면 이름만 흐려지고, 지갑 창의 숫자와도 어긋난다. 횟수만 보인다.

## 반영하지 않는 것

- 교원 정근수당의 경력환산율(별표 22) — 임용일부터 센 값으로 어림한다
