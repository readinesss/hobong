# 규정 데이터 갱신 가이드

호봉의 숫자(봉급표, 연가 일수, 승진 요건, 공휴일…)는 코드가 아니라 `data/<연도>.json` 에 있다.
법령이 바뀌면 **이 파일만** 고치면 되고, 화면의 "근거 법령"도 여기서 읽어 보여준다.

## 원칙

1. **원문에서 확인한 값만 넣는다.** 기억, 기사, 블로그, 추정으로 숫자를 넣지 않는다.
   기준은 [국가법령정보센터](https://www.law.go.kr)의 현행 법령 원문이다.
2. **값마다 근거를 적는다.** 법령·조항·개정일(`source`)과, 확인한 법령 판본(`laws`).
3. **확인하지 못한 값은 넣지 않는다.** 그 항목을 `pending` 에 적어 두면 앱은 이전 연도 값으로
   계산하면서 화면에 "○○년 표 기준(확정 전)"이라고 밝힌다. 틀린 숫자를 조용히 보여주지 않는다.
4. **발췌본을 남긴다.** 확인한 원문을 `docs/sources/<연도>/` 에 글자 그대로 저장한다.
   테스트가 데이터와 발췌본을 대조한다.

## 파일 구성

```
data/
  2026.json        그 해에 적용할 규정 전체 (status: verified)
  2027.json        2026을 이어 쓰고(extends) 달라진 항목만 담는다
  character.json   캐릭터 진화 규칙과 꾸미기(custom) (법령과 무관)
  series.json      일반직 직렬 → 호봉이 소품 테마 (공무원임용령 별표 1·2 의 직렬 이름)
  lines.json       호봉이의 한마디 (법령과 무관)
docs/sources/<연도>/   원문 발췌본
```

```jsonc
{
  "schema": 1,
  "year": 2027,
  "extends": 2026,            // 이 파일에 없는 항목은 2026년 값을 쓴다 (항목 단위, 깊은 병합 아님)
  "target": { "id": "national", "label": "국가공무원" },  // 모든 연도 파일이 같아야 한다(테스트)
  "status": "partial",        // verified: 전 항목 확인 / partial: 일부만 확정
  "verifiedAt": "2026-11-25", // 원문을 마지막으로 확인한 날
  "pending": ["salary", "payTables"], // 아직 확정 전이라 이전 연도 값을 쓰는 항목
  "notes": ["…"],
  "laws": {                   // 확인한 법령 판본
    "pay": {
      "name": "공무원보수규정",
      "effective": "2026-10-02",
      "promulgation": "대통령령 제36728호, 2026. 9. 29., 타법개정",
      "url": "https://www.law.go.kr/법령/공무원보수규정"
    }
  },
  "salary": {
    "table": { "9": [2133000, 2147600, …], "8": […] },  // 직급 → 1호봉부터
    "source": {
      "law": "pay",                          // laws 의 키
      "article": "제5조, 별표 3",
      "revised": "2026-01-02",               // 그 조항·별표의 개정일
      "snapshot": "pay-reg-table3-salary.txt", // docs/sources/<연도>/ 아래 발췌본
      "note": "해석, 반영하지 않은 예외"
    }
  }
}
```

항목(섹션)은 **열세 개**다. 일반직 기본 구역 열한 개 — `retirement` `probation` `salary` `stepRaise`
`promotionStep` `payday` `workHours` `leave` `promotion` `allowances` `holidays` — 와 직종 확대 구역 두 개
— `payTables` `tracks` — 이고(코드의 `RULE_SECTION_KEYS`), 형식은 `src/lib/rules/types.ts` 에 있다.
어느 해든 `extends` 를 따라가 열세 개가 모두 채워져야 한다.

- 기본 구역 열한 개는 **일반직(별표 3) 값**이다. 다른 직종은 이 값을 그대로 쓰지 않는다(아래 "직종을
  더하거나 고칠 때").
- `payTables` 는 별표 4·8·10·11 봉급표다. 별표 3 은 지금처럼 `salary` 에 있다. 다른 구역과 달리
  **표(`items` 의 키) 단위**로 합친다 — 개정 봉급표가 나왔을 때 바뀐 표만 넣으면 나머지는 이전 해 표를
  쓰고, 그 표가 어느 해 것인지는 `meta.payTableYear` 에 남는다.
  표에 `longServiceAddOn`(근속가봉: 금액 `amount`, 가산 횟수 상한 `maxCount`, 근거 `source`)을 둘 수 있다 —
  공무원보수규정 제30조의2 에 **금액이 정해진 봉급표에만** 넣는다(지금은 별표 11 하나). 봉급 계산에는 쓰지 않고,
  '생애 봉급' 창이 그 표의 사용자에게만 "근속가봉은 넣지 않았어요"를 밝히는 데 쓴다(아래 "생애 봉급의 계산 가정").
- `tracks` 는 계급 사다리(`ladders`)와 직종별 규정(`items`)이다.

```jsonc
"payTables": {
  "items": {
    "table10": {
      "annex": "별표 10",
      "title": "경찰공무원ㆍ소방공무원 및 의무경찰 등의 봉급표",
      "columns": [{ "key": "순경·소방사", "label": "순경·소방사" } /* … 10열 */],
      "table": { "순경·소방사": [2133000 /* 1호봉부터 */] },
      "source": { "law": "pay", "article": "제5조, 별표 1·별표 10", "revised": "2026-01-02",
                  "snapshot": "pay-reg-table10-police-fire.txt" }
    }
  }
},
"tracks": {
  "ladders": {
    "police": {
      "noun": "계급",                       // 화면의 '현재 계급'·'현 계급 임용일'
      "ranks": [                            // 낮은 계급 → 높은 계급
        { "key": "순경", "label": "순경", "payColumn": "순경·소방사" },
        { "key": "치안총감", "label": "치안총감", "payColumn": null, "selectable": false,
          "note": "별표 10 봉급표에 이 계급의 열이 없어요." }
      ],
      "source": { "law": "policeAct", "article": "제3조" }
    }
  },
  "items": {
    "police": {
      "label": "경찰", "status": "ready", "scope": "…", "payTables": ["table10"], "ladder": "police",
      "payday": { "defaultDay": 25, "note": "…" },
      "retirement": { /* 덮어쓰기 값 */ },
      "probation": { "status": "pending", "reason": "…" },   // 꺼진 항목
      "applies": { "diligence": { "law": "allowance", "article": "제7조제1항" } } // 일반직 값을 그대로 쓰는 근거
    }
  }
}
```

- 그 해 파일이 **아예 없으면** 가장 가까운 이전 연도 규정으로 계산한다. 다만 공휴일은 다른 해의
  것을 쓸 수 없어 비워 두므로, 월급날·근무일·징검다리 계산이 부정확해진다.
- `holidays.items` 는 일요일을 뺀 관공서 공휴일과 대체공휴일이다. 설날·추석 당일에는
  `"tag": "seollal"` / `"tag": "chuseok"` 을 붙인다(명절휴가비 지급일 계산에 쓴다).

## 언제 무엇을 확인하나

| 시기 | 확인할 것 | 참고 |
|---|---|---|
| 1월 | **봉급표**(공무원보수규정 별표 3·4·8·10·11), 수당 규정 | 2026년 봉급표는 2026. 1. 2. 개정됐다 |
| 6~7월 | **다음 해 공휴일**(월력요항, 천문연 달력자료) | 천문연 달력자료의 2027년분은 2026. 6. 30.에 만들어졌다 |
| 수시 | 임시공휴일 지정, 복무규정·임용령·수당규정 개정 | 지정·개정되면 그때 |

잊지 않도록 **"규정 데이터 점검" 워크플로**가 매달 한 번 돌면서 손봐야 할 것이 있으면 이슈를 만든다.
직접 확인하려면:

```bash
npm run rules:check                       # 오늘 기준
npm run rules:check -- --date 2027-01-04  # 그날 기준으로 미리 보기
```

## 하는 방법

### 새 봉급표가 나왔을 때 (예: 2027년)

별표 3 과 함께 **별표 4·8·10·11 도 같은 날 개정된다**(2026년은 모두 2026. 1. 2.). 다섯 표를 모두 확인할 때까지는
확인한 표만 넣는다. `payTables.items` 는 표 단위로 넣을 수 있고(`table10` 하나만 넣어도 된다), 넣지 못한 표가
남아 있으면 `pending` 에 `payTables` 를 남긴다. 그동안 그 표는 이전 해 값으로 계산하고 화면에 "○○년 표
기준(확정 전)"이 뜬다. 별표 4·8·10 은 별표 3 과 같은 방법(`pdftotext -layout`)으로 뽑고, 별표 11 은 두 단(1~20,
21~40호봉)이라 줄마다 (호봉, 값, 호봉, 값)으로 읽는다(테스트가 그렇게 대조한다).
별표 11 을 새 해 파일에 넣을 때는 **`longServiceAddOn` 도 함께 넣는다**(표 단위로 합치므로 빠뜨리면 이전 해 값이
이어지지 않는다 — 테스트가 막는다). 금액은 제30조의2제2항을 다시 확인해 발췌본
(`pay-reg-articles-separation.txt` 와 같은 형식)과 함께 넣는다. 제30조의2제2항은 2011년부터 2026년까지 해마다
1월에 개정되었다(발췌본에 적힌 그 항의 개정 이력).


1. 국가법령정보센터에서 공무원보수규정을 열어 **시행일과 공포번호**를 확인한다.
2. 별표 3을 PDF로 내려받아 글자로 뽑는다.

   ```bash
   pdftotext -layout 별표3.pdf docs/sources/2027/pay-reg-table3-salary.txt
   ```

   파일 맨 위에 출처·조회일을 `#` 주석으로 적는다(2026년 파일 참고).
3. `data/2027.json` 에 `salary` 항목을 넣는다. 형식은 2026년과 같고 `source.revised` 는 별표의 개정일이다.
4. `pending` 에서 `"salary"` 를 지우고, 다른 항목도 모두 다시 확인했다면 `status` 를 `"verified"` 로 바꾼다.
   `laws.pay` 를 새 판본으로, `verifiedAt` 을 오늘로 고친다.
5. `npm test` — 봉급표가 발췌본과 **한 칸도 다르지 않은지**, 호봉·직급 순으로 늘어나는지 검사한다.
   발췌본이 없으면 테스트가 실패한다.

### 다음 해 파일을 처음 만들 때

```json
{
  "schema": 1,
  "year": 2028,
  "extends": 2027,
  "target": { "id": "national", "label": "국가공무원" },
  "status": "partial",
  "verifiedAt": "2027-07-01",
  "pending": ["salary", "payTables"],
  "laws": {},
  "holidays": { "items": [], "source": { "law": "holidayRegulation", "article": "제2조·제3조" } }
}
```

`data/` 에 `<연도>.json` 을 두기만 하면 코드 수정 없이 반영된다.

### 공휴일을 넣을 때

- 관공서의 공휴일에 관한 규정 제2조(공휴일)·제3조(대체공휴일)와 그 해 달력자료(음력 명절 날짜)를 함께 본다.
- 일요일은 넣지 않는다. 대체공휴일은 날짜와 이름을 따로 한 줄로 넣는다.
- `npm test` 가 대체공휴일 규칙과 목록이 맞는지 다시 계산해 본다.
- **임시공휴일**은 지정되면 한 줄 추가하고 `source.note` 에 지정 근거를 적는다.

### 그 밖의 항목이 바뀌었을 때

값을 고치고 `source`(조항·개정일), `laws`(판본), 발췌본, `verifiedAt` 을 함께 고친다.
`tests/unit/rules-data.test.ts` 의 "법령 원문 발췌본과 대조"에 해당 값의 대조가 있으면 그것도 맞춘다.

## 직종을 더하거나 고칠 때

직종은 코드의 닫힌 목록(`TRACK_IDS`: `general` `police` `coastGuard` `fire` `teacher` `foreign`
`militaryCivil` `otherSpecial`)이다. 저장 형식이 이 목록을 검사하므로 **새 직종을 더하면 저장 형식 버전을
올린다.** 이미 있는 직종의 규정을 채우는 것은 데이터만 고치면 된다.

**해석 규칙**(`src/lib/rules/career.ts` 의 `resolveCareer` 한 곳). 항목(`FeatureKey`: `stepRaise`
`promotionStep` `retirement` `probation` `minService` `longService` `seniorTreatment` `leaveAnnual`
`leaveAdvance` `leaveCompensation` `leaveLongService` `diligence` `holidayBonus` `seniorAllowance`
`positionAllowance`)마다

1. 직종(일반직은 `byPayTable[봉급표]` 가 먼저)에 **덮어쓰기 값**이 있으면 그것을 쓴다. 값이
   `{ "status": …, "reason": … }` 이면 그 항목은 꺼진다(숫자 없이 상태와 사유를 보인다).
2. 없고 `applies[항목]` 에 **적용 근거**가 있으면 기본 구역(일반직 값)을 쓴다. 근거 법령 화면에는
   적용 조항과 함께 숫자가 나온 기본 구역의 조문·`note`(해석·미반영 단서)를 '적용하는 조문'으로 같이 보인다.
3. 둘 다 없으면 — 일반직은 기본 구역, **그 밖의 직종은 자동으로 `pending`(준비 중)**이다.

**일반직이 아닌 직종은 근거 없이 기본 값을 쓰지 않는다.** 데이터를 빠뜨리면 틀린 숫자 대신 '준비 중'이 뜬다.
`status: "ready"` 직종(경찰·소방·교원)은 테스트가 모든 항목을 덮어쓰기나 `applies` 로 명시했는지 본다.

`status` 세 값(꺼진 항목, 데이터에 쓰는 값):

| 값 | 뜻 | 화면 |
|---|---|---|
| `pending` | 원문을 아직 확인하지 못했다 | 준비 중 |
| `none` | 그 직종에는 없다(교원의 근속승진·연가보상비 등) | 해당 없음 |
| `external` | 조례·기관 기준 등 다른 규정이 정해 여기서 계산하지 않는다(소방 장기재직휴가, 교사 직급보조비) | 다른 기준 |

코드에는 네 번째 값 `input`(화면 '입력 필요')이 있다. 데이터에는 쓰지 않고, 사다리가 있는 직종에서 계급을
고르지 않았거나 목록에 없는 계급이 저장돼 봉급·정년을 셀 수 없을 때 계산이 만든다(원문 미확인이 아니므로
'준비 중'과 구별한다).

`status` 는 원문이 말하는 대로 고른다. **'표에 없다'는 `none` 이 아니다** — 비고가 다른 기준을 정하면
`external`, 모르면 `pending`. 월급날 기본값처럼 해석이 들어간 기본값은 `note` 에서 단정하지 않는다
('기본으로 뒀어요. 실제 월급날로 맞춰 주세요').

- **계급 키**는 사다리의 키다(일반직·우정 `'9'`~`'1'`, 경찰 `'순경'`…, 외무 `'1'`~`'6'`, 교원 `'교원'` 하나).
  `monthsByGrade`·`yearsByRank`·`amountByGrade` 의 키도 이 키다. 일반직의 `'1'`~`'9'` 는 저장 형식이 코드
  상수로 검사하므로 바꾸지 않는다.
- **봉급표 열 키**: 사다리 계급의 `payColumn` 은 그 봉급표(`salary.table` 또는 `payTables.items.<id>.table`)의
  열 키다. `null` 이면 봉급표에 열이 없는 계급이다(`selectable: false` 로 고를 수 없게 한다).
- 화면 글: `label`(직종 이름)·`scope`(직종 칩 아래 한 줄)·`pendingReason`(자동 준비 중의 사유)·
  `workHoursNote`·`leaveNote`·`leaveScreen`(연가 화면의 기록 시스템·저축 이월 여부)·`notes`.
  직종 이름 뒤 조사는 코드가 받침을 보고 붙이므로(`josa()`) 이름만 적는다.

## 직렬 목록과 호봉이 꾸미기 (법령 값이 아님)

`data/series.json` 은 공무원임용령 별표 1(일반직 직급표)·별표 2(우정직군)의 직군·직렬 이름을 원문 그대로
담고, 직렬마다 호봉이가 드는 소품 테마(`theme`)를 붙였다. 계산에는 쓰지 않는다.

- 원문 발췌본은 `docs/sources/2026/appointment-decree-table1-grades.txt`·`table2-postal.txt`. 직렬 이름이
  발췌본에 있는지는 테스트(`tests/unit/character-custom.test.ts`)가 본다.
- 직렬이 새로 생기면 그 직군에 항목을 더하고 테마를 고른다(테마는 `character.json` 의 `custom.props` 중
  `kind: "series"`). 이름이 바뀌면 새 이름으로 고치고 **옛 이름을 `aliases` 에 남긴다** — 저장본
  (`profile.series`)은 직렬 이름을 그대로 담으므로, 옛 이름이 사라지면 그 사용자의 소품이 기본(결재판)으로 돌아간다.
- 직렬이 없어져도 저장본은 거부하지 않는다(형식만 본다). 화면에 이름이 안 보이고 소품이 기본으로 돌아갈 뿐이다.

`data/character.json` 의 `custom` 구역은 호봉이 꾸미기(몸 색 `bodies`·볏 `crests`·깃 `plumes`·장식 `decos`·
손 소품 `props`)와 슬롯 숨김(`hide`)이다. 저장본(`character.look`)은 이 id 만 담고, **목록에 없는 id 는
거부하지 않고 보존**한다(같은 저장 형식 버전에서 목록이 늘어도 예전 사본이 백업 전체를 거부하지 않게). 그릴 때만
기본값으로 대신한다. id 를 지우거나 이름을 바꾸면 그 id 를 고른 사용자는 기본 모습으로 돌아가므로, 되도록 id 는
그대로 두고 그림·색만 고친다. 색 치환이 어느 칸에 적용되는지는 `src/lib/character/regions.ts` 머리말에 있다.

### 저장 형식 v5 에 더한 칸(사용자 데이터, 참고)

규정 데이터가 아니라 브라우저 저장본·백업 파일의 칸이다. 정의는 `src/lib/store/schema.ts`, 기본값은 `defaults.ts`,
v4 → v5 변환은 `migrate.ts`.

| 칸 | 기본값 | 검사 |
|---|---|---|
| `profile.series` | `null`(고르지 않음) | 형식만(`SERIES_KEY_RE`). 목록에 없거나 일반직이 아니어도 지우지 않는다 |
| `settings.identity.showSeriesHome` | `true` | 참·거짓 |
| `settings.card.showSeries` | `false` | 참·거짓 |
| `settings.haptics`·`sparkles` | `true` | 참·거짓(화면은 2C) |
| `settings.pointer` | `'pixel'` | `'pixel'`·`'system'` 밖이면 거부 |
| `settings.sound` | `{ sfx: false, bgm: false, master: 80, sfxVolume: 80, bgmVolume: 50, bgmTrack: 'auto' }` | 음량 0~100, 곡 id 는 형식만(`LOOK_ID_RE`) |
| `character.look` | `{ body: 'sunny', crest: 'red', plume: 'auto', deco: { pin: null, chest: null, cheek: false }, prop: 'auto' }` | id 는 형식만(`LOOK_ID_RE`) — **모르는 id 보존**(아래) |

**꾸미기 id 보존 규칙.** `character.look` 의 id 가 `custom` 목록에 없으면 저장본·백업을 거부하지 않고 그대로 둔다.
그릴 때만 기본값으로 대신하고(`look.ts resolveCustom`), 꾸미기 화면은 그 묶음을 '고르지 않음'으로 보이며 안내한다.
사용자가 다른 것을 고른 묶음만 바뀌고, 나머지 모르는 값은 다시 저장할 때도 그대로 남는다(e2e
`tests/e2e/customize.spec.ts`). 직종 `track` 은 계산 키라 이 규칙에서 빠진다(목록 밖이면 거부).

**형식은 앞으로도 지킨다(같은 v5 안의 약속).** 위 보존 규칙은 새 값이 지금 형식에 맞을 때만 예전 사본에서 지켜진다.
그래서 목록을 늘릴 때는 다음을 지킨다(`tests/unit/assets.test.ts` 가 지금 목록을 본다).

- 새 꾸미기·소품·곡 id 는 `LOOK_ID_RE`(영문 소문자로 시작, 소문자·숫자·`-`, 32자까지)를 지킨다. 밑줄·대문자를 쓰지 않는다.
- 새 직렬 이름·옛 이름(`aliases`)은 `SERIES_KEY_RE`(한글·영숫자·가운뎃점 `·`, 낱말 사이 띄어쓰기 한 칸, 20자까지)를 지킨다.
  가운뎃점·띄어쓰기는 아직 원문에 없지만 v5 에서 미리 받는다.
- 새 칸(예: `deco.hat`)을 더하거나 열거값(`pointer`)·숫자 범위(음량 0~100 정수)를 넓히면 예전 사본이 버리거나 거부하므로
  **저장 형식 버전을 올린다**(부록 C: 더 새 버전 저장본은 예전 사본이 건드리지 않는다).
- 특정직의 손 소품 `'auto'` 는 호봉 소품(9호봉부터 결재판)이다. 직종 소품(손전등 등)은 직접 고를 때만 든다 —
  직종은 꼭 고르는 계산 값이라 기본 모습·카드가 직종을 드러내지 않게(부록 F). 모르는 소품 id 도 호봉 소품으로 그린다.

### 저장 형식 v6 에 더한 칸(사용자 데이터, 참고)

생애 봉급(#30)의 **퇴직 예정 달** 한 칸만 더했다. 정의는 `src/lib/store/schema.ts`(`PlanState`), 기본값은 `defaults.ts`,
v5 → v6 변환은 `migrate.ts`(`v5ToV6`), 바꾸는 곳은 `app.setRetirePlan` 하나다.

| 칸 | 기본값 | 검사 |
|---|---|---|
| `plan.retireMonth` | `null`(정한 적 없음 = 정년까지) | `null` 이거나 `'YYYY-MM'`(`YEAR_MONTH_KEY_RE`, 연도 1930~2150). **형식만 본다** |

- `Profile` 이 아니라 최상위 `plan` 에 둔다: 내 정보 폼이 프로필을 새로 만들어 저장해도 잃지 않고, 정년·호봉 계산의
  입력과 섞이지 않는다(앞날에 대한 사용자의 가정이지 '내 정보'가 아니다).
- **v5 → v6 변환은 늘 `{ retireMonth: null }` 로 덮는다.** v5 파일에 `plan` 이 섞여 있어도(손으로 고친 파일) 옮겨 담지
  않는다 — v5 앱은 그 칸을 읽지도 저장하지도 않았으므로 사용자가 정한 값이 아니다(v4 → v5 와 같은 관례).
- **저장본 검사는 오늘·정년·임용일과 비교하지 않는다.** 시간이 지나 지난 달이 되거나 내 정보를 고쳐 정년이 당겨져도
  저장본을 거부하지 않고, 값을 말없이 고치거나 지우지도 않는다. 정년퇴직일과 같은 달도 그대로 둔다. 쓸 수 없게 된
  값은 계산(`resolveLifetimeEnd` 의 `planIssue`)이 걸러 정년 기준으로 셈하고, 화면이 "고치기 / 지우기"를 권한다.
- 고를 수 있는 달인지(이번 달 ~ 연령정년 퇴직일의 달, 정년 규정이 꺼진 직종은 2150년까지)는 입력 폼만 본다
  (`lifetime-copy.ts` 의 `checkRetirePlan`).
- 이 값은 **'생애 봉급' 창에서만** 읽는다. 카드·결산 카드·탭 제목·공유 문구와 정년 D-day·연가·보너스·일정은 읽지
  않는다(`tests/unit/lifetime-scope.test.ts` 가 읽는 파일을 묶어 둔다).
- **임용정보 패키지에는 그대로 실린다**(패키지 = 저장본 그대로). 암호를 걸지 않은 패키지에서는 읽히는 글자다 — 폼
  아래 안내가 이것을 알린다. 퇴직 예정 달만 패키지에서 빼지는 않는다(내보내기 → 불러오기 왕복 약속).
- 예전 사본(v5 까지 읽는 hobong.html)은 v6 저장본·패키지를 '더 새 버전'으로 보고 읽지도 고치지도 않는다(PLAN 부록 C).
  v6 의 `plan` 에 칸을 더하거나 형식을 넓히면 다시 버전을 올린다.

## 생애 봉급의 계산 가정 (#30)

홈의 '생애 봉급' 창은 규정 값을 새로 넣지 않고 이미 있는 봉급표·정기승급·정년·보수 지급일·정근수당 규정으로 셈한다
(`src/lib/calc/salary.ts` 의 `lifetimeSalary`, `src/lib/calc/lifetime.ts`). 문구는 `src/lib/app/lifetime-copy.ts` 한 곳에 있다.

**계산이 따르는 가정**

| 무엇 | 가정 | 근거 |
|---|---|---|
| 봉급표 | 오늘이 속한 해에 적용하는 봉급표 한 장(그 해 파일이 없으면 가장 가까운 이전 연도)을 임용일부터 끝나는 날까지 쓴다 | 지갑 창의 '지금까지 번 봉급'(`cumulativeSalary`)과 같은 방식 |
| 계급·호봉 | 지금 계급 그대로, 정기승급만(승급기간마다 한 호봉, 최고호봉에서 멈춤). 승진·강임·승급 제한·휴직은 넣지 않는다 | 공무원보수규정 제13조(`pay-reg-articles.txt`) |
| 달 가운데 임용·승급 | 그 달 날수로 나눈다 | 제22조제1항, 제4조제6호(`pay-reg-articles-separation.txt`) |
| 끝나는 날 | 기본은 정년퇴직일(연령·계급정년 중 이른 날). 사용자가 **퇴직 예정 달(연·월)** 을 정하면 그 달 말일(저장 형식 v6 의 `plan.retireMonth`, 이번 달 ~ 연령정년 퇴직일의 달). 늘 달의 말일이고 **그날까지(포함)** 봉급을 센다 | 국가공무원법 제74조제4항 등(직종별 `retirement`). 테스트가 모든 직종의 퇴직일이 말일인지 본다 |
| 날짜가 아니라 달 | 퇴직일을 날짜로 받지 않는다. 달 가운데 그만둔 달의 봉급은 근속 연수·그 달 근무 일수·퇴직 사유에 따라 전액이거나 날짜만큼이라 날짜로는 틀린 숫자가 나올 수 있다. '그 달 말일까지 다닌다'는 가정은 어느 해석에서도 그 달 전액이다 | 제22조제1항, 제24조제1항제1호(`pay-reg-articles-separation.txt`) |
| 금액의 범위 | 봉급만. 수당·세금·기여금·퇴직급여는 넣지 않는다 | — |
| 합이 맞게 | '앞으로 벌 봉급'은 따로 더하지 않고 `총액 − 지금까지`로 정의한다(원 단위 합이 늘 맞는다). 화면은 만 원 미만을 버리므로 '앞으로'만 `보이는 총액 − 보이는 지금까지`(만 원 단위)로 보인다 | `shownRemaining` |
| 월급날 횟수 | `임용일 ≤ 월급날 ≤ 오늘`은 받은 쪽(오늘 포함), `오늘 < 월급날 ≤ 끝나는 날`은 남은 쪽. 달은 끝나는 달까지만 훑는다. 주말·공휴일이면 당겨진 날로 센다 — 1~3일 지급처럼 다음 달 월급날이 이번 달로 당겨져 그날이 지났으면 받은 쪽에 들어가, 당겨지지 않았을 때보다 '남은' 횟수가 하나 적다 | 제20조제2항(토요일·공휴일이면 그 전날) |
| 정근수당 횟수 | 지급 달(1·7월) 1일에 재직 중이고, 그 앞 지급대상기간(6개월) 가운데 1개월 이상 봉급을 받았고(임용일부터 기준일까지 1개월 이상), 지급일이 아직 오지 않은 것. 금액은 세지 않는다 | 공무원수당 등에 관한 규정 제7조제1항(`allowance-reg-articles.txt`). `diligenceBonus` 와 같은 판정 |
| 해가 바뀌는 횟수 | 오늘 뒤~끝나는 날 사이의 1월 1일 수. **봉급표가 바뀌는 횟수가 아니다** | 달력 |

금액(번 날 기준, 오늘까지 일할)과 횟수(월급날이 지났는지)는 기준이 달라, 이번 달 월급날이 지난 마지막 달에는
'앞으로 벌 봉급'이 남았는데 남은 월급날은 0번일 수 있다. 화면이 그 줄에서 "이번 달 월급날은 지났어요"라고 말한다.

**넣지 않은 것과 까닭**

- 명절휴가비 횟수: 설날·추석 날짜는 그 해 공휴일 데이터에서만 온다(데이터가 없는 해가 대부분이다).
- 남은 근무일 수: 공휴일 데이터가 없는 해는 주말만 쉬는 날로 세게 된다.
- 수당을 더한 합계: 일부 수당만 더하면 이름만 흐려지고, 지갑 창의 숫자와도 어긋난다. 횟수만 보인다.
- 근속가봉(제30조의2): 조문이 "가산할 수 있다"이고 근무성적 조건이 있다. 금액이 원문에 있는 봉급표(별표 11)의
  사용자에게 넣지 않았다고 밝힌다.

## 반영하지 않는 것

개인마다 다른 사정은 데이터에 넣지 않고 화면에서 날짜를 직접 고치게 한다.

- 휴직·징계·승급 제한·경력 인정으로 달라지는 승급일과 재직기간
- 근속승진 기간 단축, 대우공무원 선발 기간 단축과 근무실적 요건
- 유사경력·성실근무에 따른 연가 가산
- 가족수당·시간외수당 등 개인별 수당과 공제(실수령액)
- 근속가봉(공무원보수규정 제30조의2), 달 가운데 퇴직하는 달의 봉급(제24조) — '생애 봉급' 창이 넣지 않았다고 밝힌다
- 계급정년의 연장(비상사태·특수 부문)·강등·재임용·자치경찰 경력 합산 — '계급정년에 이르는 날'을 직접 넣는다
- 근속승진 기간 단축(경찰·소방), 경찰 대우공무원 1년 단축
- 교원 정근수당의 경력환산율(별표 22) — 임용일부터 센 값으로 어림한다
- 별표 10·11 비고(경찰대학생·간부후보생·의무경찰·기간제교원), 치안총감·소방총감 봉급
- 교감·교장 등 교원 직위, 교사의 직급보조비(별표 15 비고 제8호 — 인사혁신처장이 정한다)
- **별표 4 행의 특정직**(국가정보원 직원·경호공무원·중대범죄수사청수사관) — '그 밖의 특정직'을 고르게 안내한다
- **법원·헌법재판소·국회 소속 일반직의 승진 규정** — 공무원임용령 값을 쓰며 실제와 다를 수 있다(T14)

## 다른 직종으로 넓힐 때

국가공무원 안의 직종은 `tracks` 로 넓혔다(위 "직종을 더하거나 고칠 때"). 지방직은 여전히 근거 규정이
달라(지방공무원 보수규정, 지방공무원 임용령 등) 값이 같아 보여도 **각각 원문으로 확인**해야 하고, 그때는
`target` 별로 파일을 나누고(`data/<대상>/<연도>.json` 등) 로더를 고쳐야 한다. 아직 하지 않았다.
